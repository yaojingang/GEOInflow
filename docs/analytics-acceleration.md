# 统计加速

GEOInflow 使用 PostgreSQL 中的持久汇总、访问事实和覆盖清单减少历史数据的重复计算。原始事件、日志和核验证据继续保存。当前尾部、无效桶和覆盖缺口按原始事实补齐；范围 UV 在合并访问事实后精确去重。

## 启用和历史构建

运行正常的应用及 `analytics-worker`，完成增量迁移后，新网站和升级后新增输入自动进入维护。网站管理者可从网站管理或网站设置打开 `/settings/analytics-acceleration`，选择网站，查看覆盖和任务记录。

历史构建支持三个范围：

- 常用报表范围：所选时区近 30 天、对比期和六个自然月趋势的共同依赖。
- 自定义范围：开始日期包含，结束日期不包含，日期按所选时区解释。
- 全部留存历史：冻结提交时仍保留的事件及日志边界。

进度来自已完成工作单元。关闭页面后任务继续运行。构建暂停会保留新增输入捕获；停用加速会关闭该网站捕获并使旧覆盖退出读取。重新启用建立新的 epoch 和捕获基线，历史范围需要重新构建。管理操作使用 UUID 幂等标识和修订号，过期操作需要先读取最新状态。

## 数据层和精确口径

| 层 | 内容 |
| --- | --- |
| 原始事实 | 现有事件、会话、日志、质量及清洗证据 |
| 变更捕获 | 同事务、语句级触发器登记 32 路叶桶修正标记 |
| 日志汇总 | UTC 5 分钟及小时低基数计数，小时路径与身份事实 |
| 访问事实 | UTC 小时内匿名 session/visit、主机、PV、custom、最早/最晚时间及支持维度 |
| 覆盖清单 | epoch、规则和清洗版本、输入指纹、候选代次与已验证空区间 |
| 展示结果 | 浏览器、进程、Redis 和持久查询任务，独立保存计算时间与有效期 |

新增大型派生表按 UTC 月分区。原始表沿用原结构。五分钟任务维护低基数计数，完整 UTC 小时关闭并经过 30 秒缓冲后构建小时路径；当前小时和旧的非整小时路径覆盖使用原始事实。候选全部完成并通过版本和租约复核后才原子发布。迟到、更新、删除、清洗发布及相关维度更正使受影响覆盖退出读取，后台再构建。

分析触发器绑定安装时的数据库 schema，独立的新连接也能正确处理 ORM 写入。替换触发器函数时需重新指定其 `SET search_path`；PostgreSQL 的 `CREATE OR REPLACE FUNCTION` 会清除本次定义省略的函数配置。变更捕获持有站点代次锁，停用和重新启用与事实事务在同一边界串行。独立数据库维护若与生命周期操作冲突，会以 SQLSTATE `55P03` 原子回滚；维护方应按网站、加速状态、子表的顺序取锁，并在冲突后重试完整事务。

普通 `/api/send` 事务保持回执、单条原始事件、地理及质量证据的原子顺序。每站固定 32 行访问锁，同一访问在原始事件入口等待前一事务提交后再读取邻居快照；证据映射先锁定原始事件，更新、删除和全族失效遇到冲突时以 `55P03` 原子回滚。链接和像素没有分析站点元数据时继续采集。

多语句、多事件维护应先按网站 ID 顺序取网站 `FOR UPDATE`，再操作分析站点及事实；现有重置、删除和清洗入口沿用此边界。直接 SQL 和开发模拟脚本执行多事件事务时也需要该维护围栏。任意无围栏的多语句 SQL 仍可能因后续语句扩展脏标记集合产生死锁，调用方应重试完整事务。滚动升级保留原采集事务顺序。

访问级事实跨小时合并后计算 UV、访问、跳出和时长；custom-only 访问和主机分组沿用原查询含义。日志保留归档身份、目录版本、原用途、AI 资格三态、识别、核验和自检维度。历史身份缺失保持未知。

浏览器设备维度与身份依据来自事件自身的采集快照。访问事实同时保留人口事件数及身份、规则、目录版本；custom 和 performance 事件参加人口完整性判断，PV、访问、跳出和时长继续各自的筛选口径。人口元数据按完整网站时间窗计算，筛选和分页后的指标仍使用该时间窗的身份可用性。身份依据不完整时，访客、访问等身份指标显示不可用，PV 与收入保持可计量。

人口事实使用新的汇总语义版本。旧代次保留供检查，新读取会拒绝使用旧版本覆盖。事件环境更正定位到受影响访问；当前 epoch 内的治理排除确认、撤销和活动成员变更使访问覆盖退出读取。结果缓存沿用强版本失效，普通单点更正保留定点重建范围。

收入资格校验按网站与收入事件定位有效事件，避免对每笔收入重复展开整站事件；来源策略、清洗结果和治理排除继续参与同一校验。

查询能力由现有 schema 和指标族控制。基础日志计数、状态、身份、路径、趋势和原生基础访客计数及支持分布可使用汇总。高级过滤、顺序、归因和未支持条件使用原查询。复杂报告继续在同一个数据库快照生成。v1 AI 日志采用半开边界，兼容查询保留包含上界的原精度条件。

私人 AI 页面将浏览人口、真实总数及趋势日期标签放在同一查询快照中合并读取。已验证的小时访问事实与缺口的原始人口先合并，再按完整 session/visit 去重；历史缺失身份继续计入观测覆盖。页面仅需要日期标签时，省去入口、地域、转化及停留等每日明细展开。UTC 小时无法准确对应所选时区自然日的范围沿用原日期读取，包括非整小时偏移和小时内跨日的历史时区转换。完整报表、公开分享及原生统计保留原读取协议。

日志缺口先合并为不重叠区间，再将各区间的时间边界直接交给 canonical 日志视图；覆盖完整的中段继续复用持久事实。月度及日/小时趋势保留既有五分钟网格的时间归属，直接归并资格、身份和用途标量，逐条日志的完整维度 JSON 由需要这些维度的聚合读取生成。两种读取共享相同的规则、清洗、自检及时间边界。

GEO 评分公式、证明标准、日快照、计算依据和趋势保持既有协议。GEO 后台计算参加共享准入，读取快照独立于历史汇总构建。

## 异步读取和缓存

兼容的私人聚合 GET 可携带 `Prefer: respond-async`。已有可用结果返回原 DTO 和 HTTP 200；冷查询登记持久任务并返回 HTTP 202、`analysisJob` 和 `Retry-After`。客户端轮询状态，完成后读取原结果。202 和错误均不写入成功结果缓存。

状态及结果读取遇到 PostgreSQL 锁等待超时（SQLSTATE `55P03`）时，返回 HTTP 503、`analysis-read-busy` 和三秒 `Retry-After`。客户端保留同一任务，按等待提示继续读取，每次重试重新核对登录和网站权限。权限失效、任务过期、计算失败及其他数据库错误沿用各自的处理规则。

任务仅接受完整私人登录和当前网站权限。提交、执行、状态及结果读取都复核权限、网站生命周期、强版本和 epoch。消费者只能读取自己加入的任务。公开分享、API key、部分 2FA 身份不进入新任务协议。未携带偏好的调用方继续原协议；ClickHouse、链接和像素沿用当前路径。

结果新鲜度与保留期分别计算：今日相关结果 30 秒，历史结果 300 秒；来源缓存的较早有效期继续生效。读取不会延长有效期。成功任务保留 24 小时，每站保留最新 20 份成功结果，单份最多 2 MiB。过期结果只能作为有时间说明的上次结果，当前任务继续计算。

持久任务在内部同时保存结果及其人口元数据，容量上限包含两者。读取、缓存预读和后台任务完成时恢复同一结果对应的元数据；数值与元数据在同一个报告快照中读取。原生数组的 JSON 结构保持不变，人口摘要通过既有响应头传递。

原生统计、访客分布、热力图、已保存目标和批量趋势图以完整快照保存结果及人口依据。批量趋势图核验并绑定全部资源版本，各资源的人口依据保留自己的资源标识。手动刷新将新结果写回相同条件的常规缓存键，后续普通读取即可复用。

浏览器后台页暂停轮询，退出页面会取消当前读取，数据库任务保持可恢复。前台累计查看 15 分钟后显示继续查看按钮。手动刷新触发新的计算；相同条件的普通并发请求复用活动任务。

## 工作预算和容量

默认每站派生统计容量为 1 GiB，全局为 8 GiB。部署可通过 `LIEKAN_ANALYSIS_SITE_LIMIT_MIB`、`LIEKAN_ANALYSIS_GLOBAL_LIMIT_MIB` 设置整数 MiB 额度，应用、日志 worker 和分析 worker 必须使用相同配置并重启生效。每站最小 512 MiB，全局最小 2048 MiB，且全局额度须覆盖每站额度；无效配置使进程启动失败。最小额度给固定结果预留保留足够的恢复空间。

构建继续预留每站 32 MiB、全局 128 MiB 给结果；压力清理线为配置额度的 80%，历史准入及容量受限任务恢复线为 90%。清理仅回收符合保留策略的未引用代次，已发布覆盖、上一代次及可重试检查点继续保护。容量变更后，原有后台协调逐批恢复符合条件的自动短单元，保留任务标识和检查点；手动任务沿用显式重试。

例如确认磁盘余量及全局用量后，可在私有 `.env` 中配置 `LIEKAN_ANALYSIS_SITE_LIMIT_MIB=2048`，全局沿用默认 8192 MiB，再通过原部署脚本更新三个服务。先核对站点用量低于新额度的 90%，再观察容量受限任务、manifest 覆盖截止及原范围报表。原始日志及事件、数据库凭据和计算时限保持原有规则；容量额度表示持久派生数据预算，实际磁盘需另留索引、原始数据、备份及维护空间。

查询任务的全局活动上限为 32，每站 8，每个消费者的普通看板与其他分析各 2，网站与全局上限共同约束两组任务。真实前台任务使用相同队列优先级10，后台预热使用低优先级0，热力图单次计算预算为 10 秒。重复加入同一任务不重复占用该消费者名额。固定 PgBoss 队列负责唤醒，数据库业务任务是可恢复的真实状态。

前端遇到 `analysis-concurrency-limited` 时，从 250 毫秒开始重试，等待间隔逐步增加至原有的 3 秒上限，以及时恢复短暂的名额竞争。服务端 `Retry-After` 提示按既有 10 秒等待边界处理；每次请求继续核对权限与并发额度。页面隐藏、取消读取及十五分钟前台等待预算继续生效。

所有重分析进程共享一个数据库重计算租约，租期 90 秒，每 15 秒续期。显式查询和 GEO 优先；增量等待 30 秒后获得下一个短单元；历史工作等待时，每五次交互让出一个单元。预热在空闲时执行。等待租约不占用数据库连接。

交互查询获得准入后最多计算 60 秒。构建 SQL 预算 5 秒、事务 30 秒；每批初始 2,000 条，失败时缩小，最小 100 条；最多四次尝试，退避 5、30、120 秒。单次队列交付可连续处理有时间和数量上限的短批次，每批释放并重新竞争共享名额，同类任务按等待时间轮转。停机信号、交互任务和构建权限均在批次之间复核。旧 worker 丢失租约后不能发布。

访问构建先按物理事件的时间与 UUID 取一页，再执行既有资格、身份、地理和完整访问元组的历史锚点查询。物理页数量与末键控制继续读取，观察到的人口行数单独累加进覆盖清单；整页事件均被排除时游标继续推进。浏览明细使用相同物理末键与满页判断，缺身份、缺父会话和 type 5 事件继续按原规则处理。

访问构建事务沿用明细读取的局部 `jit=off` 执行策略，避免扩展资格查询的编译占用短单元 SQL 预算；事务结束后恢复连接原有设置。

增量发现单独保存网站检查时间和五个固定的族游标，覆盖日志与访问的叶桶、失效覆盖及日志小时合并。每轮最多检查八个有候选的网站。每站五个族分别检查最多 32 个最新元数据桶和 32 个历史游标桶，每段最多尝试入队一项，合计最多 80 次入队尝试，低基数候选优先。最新范围和历史游标各自推进，新增关闭桶可及时进入维护。检查后推进游标；相同失败请求未重新入队时也让出下一轮名额。检查时钟、实际执行时钟和七天清理时钟分别保存，重启后继续轮转。

增量和历史短单元释放共享租约时，按恢复维护使用的相同条件保留该类其余可运行任务的等待时间。增量沿用最早更新时间，历史沿用最早创建时间；模式、代次、退避、构建租约及历史修复暂停继续参与筛选。等待信息与租约释放在同一次带 token 和 epoch 围栏的更新中提交，另一类等待时间保持原值；没有剩余可运行任务时清空本类等待时间。

每站派生空间采用 1 GiB 保守预算，实例派生表、分区和索引采用 8 GiB 实际预算，包含候选、保存结果和清理控制记录。单站预算中的 32 MiB、实例预算中的 128 MiB 预留给报表结果发布。容量达到 90% 时暂停新的历史构建；采集和已有结果继续工作。

## 存储与清理

统计加速页面提供“存储与清理”。网站管理者可以管理当前网站的无引用统计副本；平台管理员还可以切换到实例已完成任务。界面沿用中英文设置，并区分恢复的统计额度和清理前后的数据库物理大小。物理大小还受并发写入、索引和数据库空间复用影响。

默认启用自动清理，每小时检查一次并回收到期的高频和统计调度流水；统计副本及其他完成流水按 Asia/Shanghai 时区在每日 03:00 集中处理。错过当日时刻后会补执行，每个本地自然日执行一次。可设置时区、集中清理小时、保留期和容量压力回收。无引用统计版本默认至少保留 24 小时；高频检查、分析、控制、风险观察的已完成调度流水至少保留 1 小时；统计查询和构建的已完成调度流水固定保留至少 1 小时；其他纳入管理的已完成调度流水至少保留 24 小时。到期记录在相应下一轮回收。可配置保留期为 1、6、24 小时及 7、30 天。

网站或实例达到 80% 容量时可提前回收，压力回收使用至少 1 小时的版本年龄，目标降至 70% 以下。安全候选不足时保留有效数据，不扩大删除范围。当前及上一发布版本、所有保留的跨 epoch 覆盖清单、排队、运行、暂停、失败及容量受限任务的候选持续受到保护。

手动清理先生成 15 分钟有效的预览，冻结候选成员、时间截止点、策略修订、网站代次和归属。确认后逐批复核引用与权限，出现新增引用时跳过相应对象。相同请求标识返回原操作结果。停止操作终止后续批次；已提交批次保留执行记录。后台工作轮次最多 5 秒，每批最多 2,000 行，SQL 预算 1 秒、锁等待 200 毫秒；中断后的任务从已提交进度继续。

同一范围保留一份预览候选集；本人使用相同条件重复预览时复用原清单和截止点，修改条件后先释放旧清单元数据，再原子生成新预览。已有清理任务运行时暂停创建预览。显式预览的单条 SQL 预算为 15 秒，超时整体回滚。

回收覆盖日志、路径、访问及三类浏览明细派生表。完整清空一个无引用代次后，才在同一事务扣减其账本容量。原始浏览事件、会话、服务器日志明细、分类与地理证据、GEO 快照、历史修复和回退依据继续保存。存储回收不修改统计强版本、输入指纹或已发布结果。原始明细清理需要独立的历史归档协议，本轮界面保留其数据。

已完成调度流水由统一策略管理。数据库完成状态钩子及删除保护确保 PgBoss 原生维护不会提前删除用户选择保留的已完成流水；失败、取消和待重试任务沿用既有原生规则。显式回收仍通过 PgBoss 事务接口完成，并核对实例任务、候选成员、流水 UUID 和队列名称。没有明确网站归属的高频唤醒记录仅供平台管理员管理。操作及策略收据保留 180 天；到期预览与终态操作的候选清单按批释放。

新增接口为 `GET/POST /api/liekan/websites/{websiteId}/storage` 和平台管理员的 `GET/POST /api/liekan/storage`。GET 支持 `runId` 轻量读取进度；POST 支持保存策略、预览、确认和停止。所有入口要求完整私人登录，网站接口复用当前资源管理权限；每批再次核对权限、归属、策略修订和网站代次。

配置 ClickHouse 时，PostgreSQL 任务流水仍由实例清理策略管理，管理员可以通过统计加速页面查看和清理实例任务。网站派生版本回收继续要求 PostgreSQL 统计模式，切换数据库模式时保留已有网站清理任务。实例入口独立校验完整登录、公共分享上下文和写入来源。

实例及网站清理接口在 Next 路由层注册 `Cache-Control: private, no-store` 和 `Vary: Authorization`，涵盖自定义 API 前缀与基础路径，保留操作收据和实时权限信息的私有响应策略。

过期预览的清单回收会锁定对应操作，并跳过正在确认的记录，保留已确认任务的冻结成员。前台进度查看按任务独立计时，同一任务累计前台在线时间达到 15 分钟后可手动继续查看，后台清理持续执行。

保存策略的操作者失去管理权限时，自动策略停止并保留原操作者；现任管理者重新保存后恢复调度。停用更新校验策略修订，保留并发保存的新设置。

数据库回归使用 `LIEKAN_STORAGE_GC_TEST=1` 及专用本地测试数据库运行 `storage-generation-gc.integration.test.ts` 与 `storage-retention.integration.test.ts`；脚本只创建和清理自有随机 schema。完整数据对比入口为 `tests/liekan/storage-retention.integration.ts`，显式要求 `LIEKAN_STORAGE_CLONE_TEST=1`、本地 `liekan_storage_test` 数据库和隔离恢复副本，依次执行 baseline、cleanup、verify。生产数据库和其他数据库名称会被拒绝。

路径或访问事实只有在三个完整日的实测对照都满足以下条件时停止继续扩展：派生行数超过输入行数的 80%，且冷读取提升不足 20%。缺失、超时或结果不等价的样本不会触发停止。已有覆盖继续可用，缺口保持精确读取，低基数计数继续维护。

## 部署和排查

使用现有 `scripts/liekan-deploy.sh` 部署应用和分析 worker，保留已有配置、数据库凭据、容器大版本及数据卷。PostgreSQL 15、16 都支持本功能。升级现有 15 实例时继续运行 15。新增服务、账号和必填环境变量为零。正式镜像使用项目的 `Dockerfile.liekan`，沿用已有的构建内存设置。分析 worker 的运行预算保持 1 CPU、512 MiB。

部署脚本在镜像构建成功、原数据库和缓存健康后，先停止旧 worker，再更新应用及执行迁移，应用健康后启动新 worker。迁移按完整文件名和校验值识别；保留 `037_analytics_rollups.sql` 与 `037_browser_population.sql` 各自的历史记录，不手动改号或删除已应用文件。

迁移执行器在取得事务锁前及每条原始迁移语句前设置 2 秒锁等待上限。已有迁移文件中的会话设置保持原样执行，后续 DDL 使用统一上限；锁竞争失败会回滚本次迁移事务，可在冲突释放后重试。

页面长期排队时先检查 `analytics-worker` 心跳、固定队列、任务错误码和共享租约。覆盖变为待更新时查看是否存在清洗、策略或来源更正，并核对后台构建进度。容量受限可暂停历史构建或停用网站加速；原始事实继续用于统计。原始输入已删除的历史无法凭汇总创造新的核验证据。

验证入口：常规及 `--scope-c` 数据库检查均执行普通看板调度与有界浏览访问回归。`pnpm test:analytics-rollups` 在自有临时数据库中执行真实汇总、访问去重、无扫描覆盖、失效和持久任务对照；`pnpm liekan:verify --working-tree` 验证源代码、生成物和生产构建。缓存容量与规模验证见 [统计缓存](analytics-cache.md)。所有基准数据必须独立命名和隔离，结果按实际运行记录。

## 持久看板快照与当前数据更新

迁移 049、050 增加私人看板的持久结果与浏览器访问、路径事实。普通看板读取只检查当前身份、网站权限、强版本和快照身份，然后返回已发布结果。进程与 Redis 缓存失效后仍可复用数据库中的结果。首次出现的新条件通过原有持久任务协议后台生成；逐行记录、导出、公开分享和 GEO 日快照继续采用各自协议。

今日普通看板使用已闭合的 UTC 三十秒窗口，读取时保留精确的当前尾部与覆盖缺口。最近使用的组合优先进入更新，首次读取、自动读取和主动刷新可登记后台计算，旧结果在计算期间继续展示。页面每 30 秒读取并显示实际截止时间；实时页每 10 秒读取原实时接口。隐藏和离线暂停，读取未完成时合并等待。热力图、留存、归因等重分析保留五分钟后台窗口。原有 UTC 五分钟及小时汇总粒度、迟到修正、人口完整性、质量资格与 UV 去重规则保持一致。

历史结果按输入与规则版本复用。后台检查范围内的变更证据，稳定历史保持原有结果；迟到、补录、删除、属性、收入、热力图及质量依据变化会触发受影响结果更新。三十秒展示修正标记与原始写入在同一事务提交；五分钟分析汇总标记保留原有粒度，采用 32 路分片，不保存 IP 或完整 User-Agent。已完成批次的发布边界排除截止时间之后的新事件。任务登记与其快照绑定在同一事务提交，发布前再次核对输入、权限、强版本、epoch 和原有计算租约。失败或等待期间保留已有的合法结果。

后台自动登记全部留存事件与日志的历史边界，按日推进持久游标，复用有界构建单元。尚未关闭的最后一小时等待关闭后继续处理；进程重启保留游标，失败任务按退避恢复。自动历史使用历史调度通道，今日增量与迟到修正可以独立推进。停止或重新启用网站加速继续使用现有 epoch 围栏；停用时恢复原有异步精确读取。

空间回收后，自动登记的 `capacity_limited` 短单元在站点和全局用量均低于90%时重新进入队列，保留原检查点。每站每轮按日志和访问分别恢复最近的一个未覆盖单元，独立于历史发现游标；已证明完整的范围继续复用，小时路径任务另外核对路径覆盖。恢复继续核对当前 epoch、启用状态、自动任务身份和访问扩展配置；手动暂停、普通失败、失效代次与已开始回收的代次遵循原有围栏。

停用或重新启用加速时，旧 epoch 的失败与容量受限任务一并失效，后台协调也会修复历史遗留状态。失效任务的未发布检查点可进入原有回收流程；当前和上一已发布代次继续按 manifest 引用保护。

看板中已耗尽计算预算或出现计数溢出的输入保留失败标记，完成任务回收和闲置维护保留该标记。原始输入、规则、覆盖进度或可用容量发生变化后允许再次登记；用户也可主动重试。其他暂时失败采用五分钟冷却后恢复，既有四次计算尝试与执行预算保持原值。已有合法结果继续显示数据截止时间和更新失败提示。

只有已进入统计计算且耗尽其既定截止时间的数据库超时才使用持久预算失败标记。连接获取、权限校验和发布阶段的暂时故障继续采用冷却重试；查询缓存与直接报告路径保留相同错误分类。快照复用在同一事务中先持有网站权限，再锁定结果，与重置和停用沿用一致锁顺序。

前台登记达到原有名额上限时，可让同一网站、同一创建者且没有其他消费者的闲置已发布刷新让出一个席位。候选必须属于当前规则与 epoch、仍在保留期、尚未计算且已有可用结果；按实际阻塞的配额类别选择。容量、网站代次、看板与任务锁保持原有并发围栏，正在读取、运行、共享或首次冷预热的任务受到保护。让位和前台登记在同一事务提交，登记失败则一并回滚；已发布统计保留，后台维护无法主动抢占席位。全局、网站与个人上限保持原值。

登记锁争用耗尽有界重试后，最后一次核验重新读取当前授权、有效任务与消费者名额。确有配额阻塞时返回原有429；有空余名额且登记锁仍忙时保留503。已有任务和消费者沿用共享豁免，锁失败的终端核验只读。

流量总览与访客概览在同一自然日内检查输入指纹，输入未变时可将已发布结果复用到下一个三十秒窗口，同时更新报告范围、人口统计证据与数据截止点。日志导入、连接状态、接入区间、分类目录与浏览器风险处理元数据均参与失效判断；例行连接心跳、权限检查与交付租约只更新运行记录。今日指标的依赖围栏包含截止时刻的记录。跨日、权限、规则或 epoch 变化沿用原有重新计算及发布校验。

浏览器事实保留跨桶精确合并所需的 session/visit、首末事件、来源、设备、地理与路径统计。常用总览、趋势、来源、地域、设备、路径和普通目标计数读取已验证代次，边界缺口按原始事实补齐。跨日 UV 按身份去重，时长与跳出在合并访问后计算；复杂漏斗、顺序与未支持条件继续使用原有后台查询。原始事件与核验证据沿用原保留策略。

默认页面会预先登记，并记住近期实际使用的时区和语言，沿用现有默认范围；预热不改变真实访问时间。真实前台排队任务优先，每轮维护最多登记一个无人查看的普通冷预热任务，全局此类排队或运行任务最多一个。已发布结果维护与独立原生热协议保留各自准入。最近两分钟实际读取的组合采用三十秒更新，无人查看的当前常用组合采用五分钟维护，其余闲置组合保留结果并停止主动计算，已发布截止时间保持单调。跨天后预热新日期的默认组合，上一日已发布代次保留，旧的今日指标快照停止热更新；昨日尚未完成的统计在闭合后发布历史结果。数据库中的每个网站默认保留最近 200 份已完成普通快照，运行中的任务继续受队列名额限制，按最近使用回收，单份与整站空间沿用现有容量保护。重置、删除和权限变化继续围栏旧结果。

迁移 051 为事件、明细、原始日志和日志核验证据增加三十秒发布围栏，保留历史粗标记及全局失效。迁移先等待相关源表写入结束，再替换捕获函数并重绑 schema；旧迁移和原始事实保持原样。

迁移 052 补记跨时间的访问依赖：同一次访问的资格变化会重新校验此前热力图，升级后首次补全的会话身份会重新校验此前身份筛选。后续稳定身份采集沿用已有截止围栏。已保存结果保留显示值并重新进入后台校验。预热任务被前台读取后更新队列中的实际优先级，保留原任务与输入。

### 常用日期与后台需求

常用页面按现有日期选择器预热今天、近7天和近30天，先选择今日总览和今日访客概览，再完成其余今日页面，随后处理近7天和近30天。每轮维护只登记一个冷任务，预热不更新真实访问时间。200条持久结果满额时，在网站容量锁内为缺少的当前常用组合回收闲置旧结果，按最近读取顺序淘汰。最近两分钟读取的结果、关联计算任务的结果和当前常用组合受到保护；全部位置都受保护时保留既有结果，后续维护再尝试。前台新条件登记沿用相同保护约束，优先淘汰闲置旧结果或版本失效的结果；容量无法释放时保持原有空间限制。今天的逻辑窗口跨小时复用；跨日后按所选时区预热新的今天、近7天和近30天，旧窗口按相同容量规则回收。

网站容量互斥采用独立的事务级咨询锁，前台登记与后台回收共用此锁；站点共享锁继续围栏模式和代次变动，并允许历史、增量短单元与登记并行。预热轮转记时遇到站点共享锁占用时留待后续维护更新，已登记任务保持有效。

冷预热和已发布结果维护逐轮轮转登记顺序，后台维护任务持续存在时仍可登记常用冷预热，冷预热存在时已有结果也可继续维护。两条路径共用每轮一次的冷登记额度。当前常用组合在无人查看时继续按五分钟维护，其他闲置两分钟的组合停止主动计算并保留已发布结果。用户返回时，权限、强版本和代次继续核验；依赖边界、截止时间及输入指纹均未变化的已发布结果直接复用，变化时重新入队。迟到数据继续经过原有更正和发布围栏。有自动读取的今日普通看板立即返回同站点、同权限版本、同条件的已发布结果，并保留真实数据截止时间；到期结果在后台更新。主动刷新、历史更正和无自动读取的重分析页面通过既有任务句柄继续跟随新结果。

迁移053引入的独立全局单名额用于真实读者的普通页面报告，首次和重试均保留最多60秒计算预算。原生统计与浏览量保持首次10秒、重试60秒，真实读者的首次计算使用独立名额，重试使用共享重分析名额；热力图仍为10秒，其他分析保持既有预算。无人查看的普通冷预热首次使用共享重分析名额、10秒预算和低队列优先级，失败后暂停。每次领取和业务行认领都按最近两分钟已授权页面或任务读取重新核对需求；独立名额按网站选取当前可运行的任务：首次结果按真实登记时间排序，已有结果的刷新增加一个三十秒更新周期的排序偏移；任一近期实际读取的别名缺少结果时，整项任务按首次结果处理。等待较早的刷新会自然排在后来登记的首次任务前，跨站继续按真实等待时间派发，其他计算通道独立推进。正在排队或运行的预热被真实读者打开后沿用同一任务。离开页面两分钟后，失败任务和已失败的重试暂停，已有结果保留，重新打开页面按当前权限和输入登记。后台任务不再为无人查看的失败结果循环创建新的重试批次。


### 统计查询执行策略

日志覆盖缺口先限定原始主键和时间区间，再通过现有资格视图读取事实；同一报告共享缺口范围，并按实际引用的归档目录批量解析爬虫产品形态。浏览器入口使用每个访问已选定的唯一入口记录进行集合连接，人口覆盖查询省去无关的地域锚点展开。计数、身份、质量政策和边界条件保持一致。

日趋势、设备、访问热度和转化计数按字段依赖读取事实，来源与地域仅在相应报表需要时展开。指标缺口只读取已满足身份资格的原始事实；人口覆盖和持久构建继续保留未知身份观测，部分覆盖期间的资格比例保持准确。

普通看板、原生统计及浏览器明细组合查询在当前报告事务中设置 `SET LOCAL jit=off`。覆盖代次、缺口补读和质量视图展开后，短查询的计划估算可能触发大量 LLVM 编译；事务内关闭 JIT 可避免这部分固定开销。事务结束后数据库恢复连接原有设置，查询范围、质量资格、覆盖围栏与统计表达式保持一致。

分析工作进程的主连接池固定为四个连接，为两个前台计算、一个后台计算保留一个权限、租约与队列控制连接。计算闸门与数据库许可对应：正在查看的普通看板共用两个数据库许可，其他重计算沿用原有闸门。每个计算名额继续执行原有超时、权限和发布检查，等待中的同类请求保持有界。


前台统计请求派发遇到计算名额占用时，队列按1秒间隔进行最多10次派发重试；重新领取前不增加统计计算次数。统计计算总计最多四次尝试，退避沿用原规则，闲置失败任务继续暂停。首次实时预热交付预先配置相同的派发重试，用户在队列领取后打开页面时可直接衔接。后台预热继续使用低优先级与重分析名额。持久任务的五秒补发维护保留，用于队列中断与丢失交付的恢复。

页面与内容仅请求旅程、退出页时采用相同资格与时间边界的窄事件投影，避免重复展开未使用的会话和地域维度。访问旅程的首来源按完整所选窗口与既有时间、事件 ID 排序预先提取；回放列表先限定已录制的访问后聚合。转化归因在一次事务查询中复用相同的转换事件与归因时间，保留各来源分组、独立会话计数、时间相等边界及身份缺失处理。

迁移054保持回放资格的同网站、同会话、同访问 EXISTS 条件，并加入 OFFSET 0 约束资格探查，避免优化器先对全站有效事件生成访问集合。既有迁移保持不可变，升级保留原始事件、录制与已发布统计。

前台交付使用同一优先级；计算名额暂不可用时，工作进程按已领取的交付代次完成失败重派，并将该次等待交付降为低优先级，给其他可运行页面让出领取机会。统计业务行仍保持排队且不消耗计算尝试。排队交付更新继续受 PgBoss 的状态和代次围栏限制。

热页面返回已发布结果时，已提交的刷新任务通过服务端内部标记进入相同的及时派发路径；标记不进入 HTTP 正文或响应头。派发继续共用 64 项并发去重和 150 毫秒等待上限，失败后由原有五秒恢复维护补发。

独立页面名额中的真实任务完成并释放许可后，使用现有队列及时交付全局等待最久的可运行页面 head，每次最多一个。每站沿用首次结果与已有结果刷新的有界排序规则，跨站继续按真实等待顺序派发；未认领交付和共享重分析任务不触发该扫描，派发失败保留已完成结果并由五秒维护恢复。

同站当前可运行任务仍在排队时，后续前台交付等待原有一秒间隔、最多十次的有界重派。候选检查与业务行认领之间发生排序或需求变化时，工作进程重新核对排队状态、到期时间和真实前台需求；仍可等待的前台任务保留交付，终态、退避中的任务及转为后台的需求结束本次交付。计算许可与业务行认领分别确认，认领成功后才增加计算尝试。

PostgreSQL 加速启用时，当前月留存的完整月份起点与已闭合五分钟窗口共享快照。请求登记时捕获的闭合上界固定为统计结束点；跨窗口的新读取使用新快照，延迟登记与后台维护不扩大这个范围，迟到更正继续沿用输入围栏。明确的过去子月范围、未闭合首个窗口、未来月份、关闭加速及 ClickHouse 保留原请求范围，页面的读取时刻与“待观察”判断保持一致。

所有前台统计的首次排队与首次运行按一秒检查结果，避免轻查询在统一三秒检查间隔中累计等待；实际计算失败后的排队与后续运行继续采用三秒检查，计算次数和失败退避保持原值。HTTP Retry-After 与任务句柄中的检查间隔保持一致。

来源关键词使用省去地区、环境维度的访问投影，默认访问查询保持原 SQL；入口归因、访问指标、目标匹配、同站会话所有权和脱敏规则不变。收入交易列表的选定会话条件保留相关索引探查，避免每笔交易重复扫描统计窗口；跨访问的会话归属、币种、日期与金额精度沿用原规则。

今日日志内容请求使用 `analysis-rollups-v4` 中的 `staticResource` 布尔维度。该维度沿用原有静态扩展名、大小写、查询与片段边界；静态资源的错误仍计入异常请求。读取只接受相同全局版本向量、有效指纹、当前 epoch 和已闭合的五分钟日志覆盖，边界和覆盖缺口按原始记录精确补读。今日请求沿用两端包含的时间条件，今日已解析继续按 `liekan_import.imported_at` 计算。

v4 沿用全局日志与访问版本向量；升级期间旧覆盖暂时退出读取，两类统计各自保留精确原始回退。后台复用已有短单元，站点内优先处理最近26小时的日志与闭合访问恢复，再推进近期缺口及历史；站点间继续按原有服务时刻轮转。升级不删除旧代次，不清空已发布结果，默认容量保持每站1GiB、全局8GiB，部署额度配置见“工作预算和容量”。读缓存、私人查询结果和看板格式同步更新版本围栏。回滚到v3后，v3读取器拒绝v4覆盖并使用原始路径。

### 隔离整页性能矩阵

`test:analytics-rollups -- --dashboard-benchmark` 使用自有、带所有权标签的临时 PostgreSQL 与固定应用/worker 镜像。正式1M输入由50万浏览器事件和50万日志组成，辅助身份、质量证据和额外采集事件单列；`--distribution uniform` 与 `--distribution hotspot80` 分别建立独立数据库。优化候选的两个核心页面各执行100次已发布HTTP读取和100次逻辑冷计算，标准五组合执行100轮并发打开。每轮保留至少四个首读200及一个冷结果，记录增量与历史短单元、完整公共统计哈希、schema校验、队列与完成时间；标准组合中的冷项独立检查排队p95≤2秒、完成p95≤5秒。10K联调保留相同流程，每项采样五次。

核心冷计算、标准五组合、双冷及增长采样遇到消费者额度限制时沿用页面客户端的三秒等待协议，保留首次 HTTP 状态、每次限流与等待记录，从首次打开计算完成耗时。等待后直接得到已发布结果的样本，需要以同站、同消费者、同参数、当前代次、相同发布时间及统计哈希关联真实生产任务；排队门禁从首次请求计至真实任务开始，原始服务端入队至开始间隔另列诊断。无法证明生产任务或缺少时钟的样本保留未观测状态，门禁按缺证据处理。raw 与旧版 baseline 保留原有服务端入队至开始诊断，live 冷计算以完整生产任务证明计入有效样本。十冷突发继续独立记录合法终态 429。

基准准备构建最多执行 10,000 个真实工作单元，并在二十分钟墙钟边界内遵循持久租约和退避时间；未认领的调用只记作等待。此边界仅约束测试准备，页面完成耗时与生产预算继续分别核验。状态、尝试次数、下次执行时间、租约、检查点与进度写入自有测试目录。生产失败或准备超时会使测试失败。历史增长前后两组 HTTP 采样沿用同一消费者及既有三秒准入等待协议。

生产任务的完整统计哈希采用公共响应相同的网站投影：网站 ID、名称、域名和数字编号取自独立的权威网站行，其余统计内容保持原值。任务存储包、消费者、参数、代次、发布时间与起止时钟的验证继续保留，跨站包和统计内容差异仍使证据校验失败。

双冷组合在独立阶段执行100轮，每轮自然排空前一轮任务后，同时提交两个没有快照的组合。两个独立冷计算均须关联真实生产任务并最终返回200，返回202时继续跟随原句柄，并逐项校验报告契约及对应统计哈希；完整完成时间按每轮墙钟统计，p95目标不超过12秒，单独保留两个任务的排队时间。10K联调执行五轮。

十冷突发记录三个站点、两个消费者的全部十个终态。已受理请求要求200及正确报告契约；429要求 `analysis-concurrency-limited` 和对应配额证据。监测记录必须非空，同时核对容器运行、OOM/退出状态，并在突发期间提交一次真实采集且核对已提交事件。实际500、未完成202、无配额证据或采集失败都会保留并使门禁未达。

活跃新鲜度持续真实读取标准五组合，正式运行每个组合至少记录100次 `observedAt`、`dataThrough` 和两者时间差。数据截止落后p95≤60秒单独验收；一次迟到记录的+1传播另行记录。历史增长两臂在相邻阶段执行，边界等待该轮已登记的读者、构建及其后继单元完成，并继续检查新出现的前台需求。后续自动预热与历史发现可以正常推进，验收记录边界处仍在运行的维护任务，保留原有配额、超时和延迟门槛。新增旧浏览器事件使用独立旧session/visit及真实父会话和合格证据，核对今日输入与覆盖未变化。

旧版本基线采用最多五次的有界真实诊断，首次观测到预算失败后标记 `censored` 并保留实际样本。返回200的基线结果继续要求与同一冻结数据的契约和统计哈希精确相等；未完成诊断保留空的p95结论。优化候选的完整矩阵与旧基线诊断分别报告。Vitest机械执行完成与性能门禁通过分别显示，原有超时、TTL和生产配额保持原值。

接入身份观测的独立 SQL／两秒预算检查使用自行创建的最小表结构：准备全新且仅用于测试的本地 PostgreSQL 数据库（名称以 `installation_observation_` 开头），将其连接设置为 `DATABASE_URL`，并设置 `LIEKAN_INSTALLATION_OBSERVATION_TEST=1`，运行 `pnpm exec vitest run src/lib/liekan/upstream/installation-observation.integration.test.ts`。该测试会建表并清空其测试表，因此应使用独立空库；普通汇总测试使用已迁移 schema，二者分别运行。


### 首次蜘蛛报表读取与视图生命周期

迁移 066 增加两个全局前台读取许可和浏览器读取租约。Web 与 worker 共用这两个许可，发布继续校验 slot、token、epoch。旧的独立许可表保留；新读取会等待仍持有旧许可的进程退出。升级时按部署脚本停止旧应用和 worker，再启动同一版本的新应用与 worker；新增迁移保留，回滚应用前先停止新进程。

私有蜘蛛页面的每次共享网络读取携带 `X-Liekan-View` UUID。已有有效结果直接返回；新条件在持久登记后可使用现有整页执行器尝试有界快读，预检与计算共享 750 毫秒预算。预检读取有效 manifest 所引用的实际汇总事实和有索引的物理缺口，manifest 的 row_count 单独表示来源行数；任一数据族超过 25 万条汇总事实或 2 万条原始缺口即交给后台。总览预检覆盖六个月曲线依赖，蜘蛛列表覆盖对比期；强制刷新、非蜘蛛页面、超过 90 天和非 v1 指标走原任务路径。预检通过仍需执行原查询、权限、输入代次、容量和发布检查。快读超时或容量预检不合适时，同一任务立即恢复排队，保留尝试标记，不消耗后台计算次数、不新增失败退避。新的快读先让位给全局等待最早的可运行网站。

返回 202 的浏览器共享传输拥有独立的 15 秒租约，轮询续租。离开页面或完成读取后，通过任务路由 DELETE 释放当前 actor 与 viewer 的租约；其他标签页、其他用户和已经运行的 SQL 保持各自生命周期。未执行且失去全部真实读取需求的任务暂停，正在运行的 SQL 在原预算内完成。旧消费者及未携带读取标识的既有客户端继续使用原有生命周期。每个任务与用户最多保留 32 个读取租约，登记时回收过期记录；任务清理同时回收租约。

HTTP `X-Liekan-Read-Path` 区分 published、foreground、queued，`Server-Timing` 记录登记与快读耗时，原有尝试诊断增加 foreground/worker 路径。所有时间仅用于观察，统计 DTO 与页面保持现有契约。

历史自动建档在独立读取事务中查找原始时间边界，随后按站点使用短事务重新核对 epoch、启用状态与删除状态，并登记历史任务。站点权限锁只覆盖登记操作；原始数据边界扫描期间，前台登记仍可取得原有共享权限锁。边界读取后 epoch 或网站状态发生变化时，本轮跳过该站点，下一轮重新发现边界。

`node tests/liekan/analysis-rollups.integration.mjs --first-load-benchmark --log-rows 9000000 --browser-rows 9000 --candidate-image <image> --baseline-image <image>` 在自有临时库中生成 30 天、每天 30 万条日志以及单列的 9,000 条浏览器辅助事件，使用相同已有汇总比较四个蜘蛛页面的今天、7 天、30 天和非整日自定义范围。每个组合 3 次重启应用及 worker 后的冷读取、9 次已发布读取；数据库缓存保持温热。逐次保存失败、任务时间及完整统计哈希，结果层首次加载和数据库缓冲池冷启动分别解释。

联调档位 `--log-rows 30000 --browser-rows 900` 只对蜘蛛总览四个范围各做一次冷读取。`--browser-rows` 独立指定辅助浏览器事件量，报告保留两种输入的实际落库计数。`--retain-fixture` 仅用于首次加载基准，在运行结束后保留带所有权标签的临时数据库供复核，输出容器名；复核完毕后核对标签再删除该数据库及其匿名卷。

读取与任务调度的针对性数据库回归使用 `node tests/liekan/analysis-rollups.integration.mjs --scope-reads`，覆盖持久查询、看板发布和读取调度；完整相关数据族回归继续使用 `--scope-c`。

容量扩展与轮询权限锁的回归使用 `node tests/liekan/analysis-rollups.integration.mjs --scope-capacity`。该检查在自有临时库中验证容量受限检查点的原位恢复、汇总与原始计数一致，以及网站锁释放后原查询句柄可继续读取。

视图登记与状态续租在事务内持有对应任务的共享键锁，多人读取可以并行。取消和闲置回收先用独立语句取得可用任务的排他锁，再用下一条语句的新快照核对消费需求；正在登记或续租的任务跳过本轮回收。该两步流程保证读取与离开并发时保留有效消费者。

独立汇总读取事务沿用报表事务的 `SET LOCAL jit=off`，避免覆盖、修复和归档目录展开后的编译开销。该设置随事务结束恢复，查询时间预算保持原值。

原始日志缺口先通过 `range_agg` 合并为互不重叠的半开区间，再逐段使用 `(website_id,created_at)` 索引读取物理键。日志计数与路径缺口共享同一并集，重叠缺口只读取一次。查询外围存在多个空缺口时，已覆盖的中间时间段保持在汇总读取路径。

蜘蛛列表的前期对比复用既有精确路径汇总，沿用前期边界、身份范围、产品形态和分类过滤；缺少覆盖时回到原查询。未附加日志筛选的 v1 明细游标通过显式 `classificationSet` 投影读取同一人口的分类版本集合，NULL 与 legacy 处理沿用原语义，默认汇总结果结构保持一致。自动看板登记可合并同站点、条件、语言和输入版本下不同授权用户的活跃任务，各消费者分别校验权限和登记需求；手动刷新保留原有规则。

冷读取在登记期间遇到已有生产任务刚刚发布时，回滚本次多余任务及消费者，再重新经过完整看板读取流程。重新读取继续核对权限、版本、时间水位及输入指纹；该路径只服务自动冷读取，主动刷新和真实限额拒绝保留原行为。

返回已有结果的 HTTP 200 可以同时派发后台刷新。该响应没有轮询句柄，对应 viewer 沿用两分钟的看板需求窗口；延长只作用于当前 actor、viewer 和仍在运行的任务，不复活已释放的租约。延长失败仍交付已有结果，过期后按正常闲置规则回收。冷读取的 202 保持 15 秒续租。标签页从隐藏状态恢复时可重新登记，每轮登记使用新的 viewer；旧轮次迟到的 DELETE 只释放旧轮次。持续可见状态下的快速重复失败保留原有重试节流，状态读取和释放使用相同的私有任务地址校验。

Redis 计算锁的释放拥有独立且最多 150 毫秒的清理网络预算，计算截止后仍尝试执行 token 匹配的释放脚本。该清理不延长 SQL 或计算截止时间，避免快读转入原后台任务后继续等待自身未释放的缓存锁。网络不可用时保留租约自然到期的恢复边界。

## 报表模块复用与输入摘要

迁移 069 保存私人看板的可重建模块。主统计和图表分别按精确范围、条件、规则与输入指纹复用；v1 日志趋势将闭合历史与当前尾部分开读取，六个月趋势按自然月复用。浏览器 UV、访问、跳出与时长继续合并访问事实后计算。公开分享、逐行日志和导出保持原路径。模块不保存原始 IP、完整 User-Agent 或逐访客明细。

模块每站最多 200 份，单份最多 2 MiB，闲置七天后回收；空间计入现有站点和实例预算，并保留整页结果发布额度。模块读失败时，在原请求期限内关闭失败事务、停用本轮模块缓存并重算一次；源查询失败继续返回原错误。保存前重新核对权限、代次和输入，授权与保存共用最多 750 毫秒的绝对期限，并受原请求期限约束；存储争用不会阻止合法整页结果发布。

迁移 070 增加 UTC 日期、数据族和 32 路分片的变更摘要。同一事务按日期和数据族合并到一个事务分片，减少批量写入；原始变更标记继续保留，摘要与标记同事务更新。后台每轮最多补建 2,048 个原始标记键，完成前使用原指纹。完成后，完整日读取摘要，当前日及边界保留原精度标记；全局变更、迟到修正、删除、截断和 epoch 继续参加失效。摘要与模块均位于原 PostgreSQL 数据库，不增加服务或配置。

四类 v1 AI 看板可在本地同日、指标和证据依赖未变时复用结果并推进截止时间。蜘蛛对比范围新增的历史前缀和页面内容年龄跨日需要重新计算。授权、半开边界、人口依据及证据快照共同核验。队列在历史维护前及看板维护批次之间派发已登记的读取任务，现有并发和公平调度限制继续生效。

内部看板格式为 `dashboard-snapshot-v5`，统一统计读取版本为 `analytics-read-v4`。升级时停止旧应用与 worker，完成增量迁移后启动同一版本；回退时先停止新进程并保留新增表，旧版本继续使用原查询与汇总。原始事件、日志和用户凭据保持原样。
