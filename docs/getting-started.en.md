# Quick start

**English** | [简体中文](getting-started.md)

This guide takes one website through deployment, ingestion, data checks, and its first analysis. See the [deployment guide](deployment.en.md) for deployment commands and production operations.

Other linked reference guides are currently in Simplified Chinese.

## 1. Start the instance and sign in

Prepare `.env` in the repository root using the [installation guide](warehouse.md#新安装与应用升级), then start the ClickHouse stack.

```sh
docker compose up -d
```

Once the services are healthy, open `http://127.0.0.1:3002` in a browser. A fresh installation uses `admin` with the initial password `liekan`. Change the password in account settings. Existing instances continue to use their saved accounts and passwords.

The first full sign-in asks you to confirm the country and analytics timezone. China defaults to `Asia/Shanghai`; for other countries, choose the appropriate city. Countries with multiple timezones require a city selection. Today then follows the calendar day in that timezone. The browser's system timezone and interface language remain independent.

## 2. Create a website

In website management, create a website with its name and actual domain, and choose personal or team ownership. Open its traffic overview and data ingestion settings from the website list.

Browser scripts, log sources, content inventories, events, and goals belong to a specific website. Use a separate test website to keep ingestion exercises independent of production business data.

## 3. Install the browser script

In the website's Data Ingestion settings, select JS. Copy the generated code into the `<head>` of the site's shared page template, then publish the site.

The code has the following structure. Use the actual address and website UUID generated by the application:

```html
<script
  defer
  src="https://stats.example.com/script.js"
  data-website-id="YOUR_WEBSITE_UUID"
></script>
```

`stats.example.com` represents the analytics domain you host. The website number in application page URLs and the collection UUID have different purposes. Copying the generated snippet preserves the correct value.

Open a normal page, check that the script and ingestion requests succeed, then return to the ingestion checks. Browser PV collection can work without trusted ingress evidence; interpreting identity metrics such as UV depends on correct reverse proxy configuration. See [trusted browser identity ingress](local-deployment.md#浏览器身份的可信入口).

Events, performance, heatmaps, and recording require their own inputs or configuration. With only the basic browser script installed, extended pages show the relevant missing-input state.

## 4. Connect crawl logs

The browser script covers visits that execute it. Observing AI crawlers requires request logs from the website's server or CDN. Choose an approach that fits the existing environment.

| Method | Suitable for | Prepare first |
| --- | --- | --- |
| Manual log import | Initial validation, historical data, or a temporary gap in automatic collection | Combined or supported JSON logs for this website |
| One-time server installation | Servers you manage, Nginx / Apache, or BaoTa | Log directories, read-only access, and Docker or a supported systemd environment |
| Cloudflare authorization | Websites proxied through Cloudflare with the required logging capabilities | Configured platform OAuth, a matching Zone, and provider permissions |

### Validate a manual import first

In the website's log import page, select `Nginx / Apache Combined` or `JSON`, then upload a file or submit data using the page template. Check timestamps, request paths, status codes, and UA fields in the preview.

The interface currently specifies a maximum of 1,000 JSON records per batch, or 10 MiB and 10,000 lines per Combined batch. Split larger files into batches and review duplicate-import and source-interval notices. Import only logs that belong to the website and were obtained under the applicable authorization.

After import, inspect valid rows, rejection reasons, and processing status, then open AI crawler analytics. Logs without a matching identity retain an unidentified or unmatched state. Identities based only on UA claims remain unverified.

### Configure continuous collection

In the website's Data Ingestion settings, select the one-time server installation and follow the generated instructions for that website. Alternatively, complete Cloudflare authorization, select the Zone, and confirm the task configuration and costs.

The automatic setup first checks public HTTPS, credentials, worker heartbeats, installation assets, and provider configuration. Missing requirements are explained on the page; complete them and rerun the checks. On its first run, the server collector starts at the end of the file. Historical entries can be added through manual import.

See [automatic log ingestion](automatic-logs.md) for setup details, network interruptions, log rotation, and retransmission behavior.

## 5. Import a content inventory

Open content inventory management and import actual pages through Sitemap XML, CSV, or JSON.

- Sitemap XML currently supports `urlset` page lists. Expand a sitemap index into its individual lists before importing them.
- CSV / JSON uses a `url` or `path` field and can include existing content metadata.
- After import, check the page count, paths, and website host, and retain the actual update timestamps.

The known page set is used to assess coverage and blind spots. If the inventory covers only part of the website, interpret results against the imported set. Without an inventory, metrics that require its denominator report the missing input.

## 6. Run the first analysis

| Page | Check first | Next step |
| --- | --- | --- |
| Traffic overview | Browser activity, AI requests, sources, and the actual data cutoff | Confirm browser and log inputs separately |
| Crawl overview | Crawl trends, identities, time periods, and response status | Observe changes in purposes and errors |
| AI crawlers | Identity records, purposes, recent activity, and verification status | Filter training, search, user-triggered access, and other purposes |
| Crawled pages | Page rankings, repeated requests, directory distribution, and blind spots | Review important content and unusual paths |
| Search engines and referrals | Traditional search and AI referral sessions | Inspect landing pages and goal conversions |
| Crawler analysis panel | Sources, responses, risks, and handling records | Decide whether further investigation or a policy preview is needed |

The main entry points support Today, 7 days, 30 days, or a custom range. Pages show actual dates and timezones. When a chart has its own date controls, interpret it using that chart's stated window.

Standard Today dashboards generally read results every 30 seconds. Realtime visitors cover the most recent 30 minutes. New conditions that require a background calculation show task or update status. Log receipt confirmation and processing completion are displayed separately, so recent data can still be awaiting processing.

## 7. Configure goals, sharing, and exports

Save actual business events or page goals in goal management, then inspect conversions and funnels. Without configured goals, related conversion fields retain a missing state.

Authorized users create public shares with selected modules, dates, and access settings. New shares save the publisher's timezone and default date range; the visitor's device timezone does not redefine today. Exports use the current conditions or the conditions fixed at submission. Check dates, timezones, states, and field descriptions in each file.

GEO Weight, management, and maintenance features have separate permission and public-sharing boundaries. See the relevant pages and [page coverage](ui-coverage.md).

## 8. Investigate empty data

| Symptom | Check in this order |
| --- | --- |
| No browser visits | Website UUID, script address, browser requests, domain, and ingestion checks |
| Logs exist but no AI requests appear | Import processing results, current identity rules, purpose filters, and identity filters |
| An identity is unverified | Whether the source supplies usable addresses, applicable official ranges, verification version, and observation time |
| Inventory coverage is unavailable | Inventory import, matching paths, and sufficient source observation scope |
| UV is unavailable while PV has values | Trusted ingress and the evidence used for anonymous identity |
| A page is queued | `analytics-worker` health, acceleration tasks, error codes, and capacity |
| Today is empty while historical data exists | Account timezone, actual dates, and the latest receipt and processing timestamps |
| GEO Weight is empty | Complete observation duration, in-policy identities, and archived verification evidence |

For details, see [AI crawler analytics](ai-crawler-analytics.md), [traffic evidence](traffic-evidence.md), and [analytics acceleration](analytics-acceleration.md).
