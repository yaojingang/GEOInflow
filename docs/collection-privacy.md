# 采集 URL 的隐私边界

浏览器 tracker 在发送前清理页面 URL 和 referrer，采集接口在写入新事件及性能数据前执行同一规则。规则替换敏感参数、凭据及已识别的敏感路由后的值；普通页面名、UUID、十六进制内容 ID、数字 ID、日期和版本号保留。路径使用独立的敏感名称规则，普通 `code`、`email`、`phone`、`mobile` 目录不会因为与查询参数同名而合并。hash 路由也执行路径处理。导航比较仍使用原始地址，因此两个脱敏结果相同的地址仍可分别产生页面访问。

例如 `/articles/<UUID>` 的不同页面保持独立；`/reset/<value>`、`/token/<value>`、`/verify/<value>`、`/invite/<value>`、`/share/<value>` 和 `/s/<value>` 等已识别敏感路由会替换对应值，报表有意按脱敏路径归并。URL 的形状不能证明普通 ID 是否私密；业务若在其他路径放入秘密值，仍需在采集前排除该页面或进行业务侧清洗。

可选录屏在事件进入缓冲及切片前清理页面元数据、导航事件、已识别的 DOM URL 属性、图片候选列表，以及样式中的 `url()` 和 `@import` 地址。增量 DOM 和样式变更使用同一处理。节点 ID、时间、坐标、样式的非 URL 内容及普通资源地址保留；原有输入遮罩、默认严格文本遮罩和显式 moderate 设置继续生效。含秘密值的资源地址会改变，回放可能无法加载对应资源。

热图在入队时清理点击和滚动事件的 URL，服务端在保存路径前再次脱敏。坐标、滚动比例和按原始地址判断导航的行为保持不变；热图存储继续使用不含查询和片段的路径。

录屏服务端再次清理完整事件，以及同一请求内可以完整重组的旧格式片段组。片段 ID、顺序与事件计数保留。**跨请求未完整到达的旧片段无法单独可靠解析 URL，仍按旧协议保存。** 新版 recorder 在切片前处理完整事件，覆盖其自身生成的片段。升级需要同时发布应用和 recorder 脚本，并更新静态脚本缓存；仅升级服务端不能保证旧 recorder 的跨请求片段已脱敏。后续若要求服务端强制覆盖所有旧片段，需要带大小、时限、并发和失败恢复约束的重组协议，或明确停止接收旧片段。

规则不承诺识别任意业务秘密。未识别的业务字段、DOM 自定义属性、嵌入数据或 blob 资源内容、非标准 CSS 表达式仍需网站自身的遮罩或阻止采集设置。输入和正文的保护依赖录屏遮罩配置。本次处理只影响新采集的数据，不改写历史事件、录屏、日志、备份或升级前已经入队的消息。

## ClickHouse 仓库

浏览器事件、性能、完整录屏事件和热图均在组装持久队列输入之前清洗。消费者沿用已清洗的事实包发布到 CH，报表和导出读取已发布事实；PG 不新增对应分析事实。脱敏不重写事件 UUID、回执、访问标识和去重指纹，因此不同敏感页面访问仍分别计数，同一带回执请求的重试仍只计一次。普通内容 ID 保留原路径，不合并页面和热图。

`tests/liekan/warehouse-privacy.integration.ts` 使用独立安装验证实际构建的 tracker、HTTP 采集、Kafka 原始消息（含录屏解压）、CH 已发布事实及中英文 ZIP 导出。先用 `warehouse-fresh.integration.ts` 的 install 阶段建立新的隔离库，两个脚本使用相同的 `WAREHOUSE_FRESH_DIRECTORY`，并显式设置 `WAREHOUSE_SCHEMA_TEST=isolated-round2`。此检查不适用于生产数据库。PG→CH 历史迁移保持源值及核验摘要，不会补做历史脱敏。

## 日志导入

手动日志和自动日志沿用既有路径语义：解析后的日志事实去掉查询和片段，保留规范化路径；来源日志、传输批次及待处理内容可能仍包含原始请求数据。路径参与手动导入的事件指纹、页面目录关联和后续证据核验，Cloudflare 的原始请求 URI 还参与自动事件标识与内容摘要。

直接套用浏览器的路径替换规则会合并不同页面，改变导入去重和目录匹配，并使新旧日志口径不一致。因此本次不修改日志解析、标识、原始输入或历史数据。日志若要提供同等级的路径隐私保护，应另行定义原始证据与展示路径的保存策略、规则版本，以及导入重试和历史对账边界；不能通过替换公共的 `canonicalPath()` 隐式改变现有语义。
