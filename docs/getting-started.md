# 快速开始

[English](getting-started.en.md) | **简体中文**

这份指南按“部署、接入、核对数据、开始分析”的顺序完成一个网站。部署命令与生产运维见 [部署指南](deployment.md)。

## 1. 启动实例并登录

按[安装说明](warehouse.md#新安装与应用升级)在仓库根目录准备 `.env` 后，启动 ClickHouse 版。

```sh
docker compose up -d
```

等待服务健康后，用浏览器打开 `http://127.0.0.1:3002`。首次安装账号为 `admin`，初始密码为 `liekan`。进入账户设置修改密码；已有实例继续使用已保存的账号和密码。

首次完整登录需要确认国家和分析时区。中国默认 `Asia/Shanghai`，其他国家按具体城市选择；包含多个时区的国家需要确认城市。之后的今天按该时区的自然日定义，浏览器系统时区与界面语言各自独立。

## 2. 创建网站

在网站管理中创建网站，填写名称和实际域名，选择个人或团队归属。后续从网站列表进入该网站的流量总览和数据接入。

浏览器脚本、日志来源、内容目录、事件和目标都归属具体网站。创建测试网站进行接入演练，可以让测试数据与正式业务保持独立。

## 3. 接入浏览器脚本

在网站设置的“数据接入”中选择 JS，复制该网站生成的代码，放到网站公共页面模板的 `<head>` 中，再发布网站。

代码结构如下，实际地址和网站 UUID 以页面生成结果为准：

```html
<script
  defer
  src="https://stats.example.com/script.js"
  data-website-id="当前网站的UUID"
></script>
```

`stats.example.com` 代表自己部署的统计域名。网站页面地址中的编号和采集 UUID 有不同用途，复制生成代码可以保留正确值。

打开一个正常页面，检查脚本与接收请求是否成功，再返回接入检查。浏览 PV 可以在缺少可信入口证据时采集；UV 等身份指标的解释依赖正确的反向代理配置，见 [可信入口](local-deployment.md#浏览器身份的可信入口)。

事件、性能、热力图和录制需要各自的数据输入或配置。仅安装基础浏览脚本时，缺少输入的扩展页面会显示相应状态。

## 4. 接入抓取日志

浏览器脚本覆盖执行脚本的访问；AI 爬虫观察需要网站服务器或 CDN 的请求日志。按现有环境选择一种方式。

| 方式 | 适用情况 | 先准备什么 |
| --- | --- | --- |
| 手动日志导入 | 首次验证、补充历史或暂时缺少自动采集 | 当前网站的 Combined 或受支持 JSON 日志 |
| 服务器一次安装 | 自己维护服务器、Nginx / Apache 或宝塔 | 日志目录、只读权限、Docker 或受支持 systemd 环境 |
| Cloudflare 授权 | 网站经 Cloudflare 代理并具备相应日志能力 | 已配置的平台 OAuth、匹配 Zone 及提供方权限 |

### 先用手动导入核对

在网站的日志导入入口选择 `Nginx / Apache Combined` 或 `JSON`，上传文件或按页面模板提交。预览时核对时间、请求路径、状态和 UA 字段。

当前界面标注 JSON 每批最多 1,000 条；Combined 每批最多 10 MiB、10,000 行。大文件按批次处理，并检查重复导入和来源区间的提示。只将属于该网站、按实际授权取得的日志导入正式站点。

导入后查看有效行、拒绝原因和处理状态，再进入 AI 爬虫页面。日志中没有匹配身份时会显示未识别或未匹配状态；仅凭 UA 声明的身份保持未核验。

### 再配置持续采集

在网站“数据接入”选择服务器一次安装，按页面生成的该网站专属步骤执行；或者完成 Cloudflare 授权、选择 Zone，并确认任务配置与费用。

自动入口先检查公网 HTTPS、密钥、后台心跳、安装资产和提供方配置。缺项时展示配置说明，完成后重新检查。服务器采集器首次从文件末尾开始，历史部分可用手动导入补齐。

操作细节和断网、轮转、重传行为见 [自动日志接入](automatic-logs.md)。

## 5. 导入内容目录

打开“管理内容目录”，使用 Sitemap XML、CSV 或 JSON 导入实际页面。

- Sitemap XML 当前支持 `urlset` 页面列表。Sitemap 索引需要先展开，再导入具体列表。
- CSV / JSON 使用 `url` 或 `path` 字段，可带已有内容元数据。
- 导入后核对页面数量、路径与网站主机，保留实际更新时间。

已知页面集合用于覆盖与盲区核对。目录没有完整覆盖网站时，按已导入集合解释结果；未配置目录时，依赖目录分母的指标会说明缺失。

## 6. 完成第一轮分析

| 页面 | 先看什么 | 下一步 |
| --- | --- | --- |
| 流量总览 | 浏览、AI 请求、来源及实际数据截止时间 | 确认浏览与日志是否分别有输入 |
| 抓取总览 | 抓取趋势、身份、时段与响应状态 | 观察用途和错误变化 |
| AI 爬虫 | 身份台账、用途、最近访问、核验状态 | 按训练 / 搜索 / 用户触发等条件检查 |
| 抓取页面 | 页面排行、重复抓取、目录分布和盲区 | 核对关键内容与异常路径 |
| 搜索引擎与来源 | 传统搜索和 AI 引荐会话 | 查看落地页与目标转化 |
| 蜘蛛分析面板 | 来源、响应、风险和处理记录 | 判断是否需要进一步检查或策略预览 |

主要入口可以选择今天、7 天、30 天或自定义范围。页面显示实际日期和时区；图表有自己的日期按钮时，按图表标注的窗口解释。

今日普通看板通常按 30 秒节奏读取，实时访客使用最近 30 分钟。首次新条件需要后台计算时，页面显示任务或更新状态。日志接收确认与处理完成分别显示，近期数据还可能处于待处理状态。

## 7. 设置目标、分享与导出

在目标管理中保存实际业务事件或页面目标，再查看转化与漏斗。未配置目标时，转化相关字段保留缺失状态。

公开分享由有权限的用户创建，并按选定模块、日期和访问设置提供报告。新分享保存发布者的时区与默认日期，访问者设备的时区不会重新定义其今天。导出按当前条件或提交时固定的条件生成，核对文件内的日期、时区、状态和字段说明。

GEO 权重和管理、维护功能有独立权限与公开分享边界，具体以各页面及 [页面覆盖](ui-coverage.md) 为准。

## 8. 数据为空时如何排查

| 现象 | 检查顺序 |
| --- | --- |
| 浏览访问为空 | 网站 UUID、脚本地址、浏览器请求、域名与接入检查 |
| 有日志但没有 AI 请求 | 导入处理结果、当前身份规则、用途与身份筛选 |
| 身份显示未核验 | 来源是否提供可用地址、适用官方范围、核验版本和观测时间 |
| 目录覆盖不可用 | 目录是否导入、路径是否对应、来源观察范围是否足够 |
| UV 不可用而 PV 有值 | 可信入口和匿名身份依据是否完整 |
| 页面排队 | `analytics-worker` 健康、统计加速任务、错误码和容量 |
| 今天为空，历史有数据 | 账户时区、实际日期、最新收到和处理的数据时间 |
| GEO 权重为空 | 完整观察时长、政策内身份及归档核验证据是否满足条件 |

详细判断见 [AI 爬虫分析](ai-crawler-analytics.md)、[流量证据](traffic-evidence.md)与[统计加速](analytics-acceleration.md)。
