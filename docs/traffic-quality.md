# 浏览流量质量与统计策略

Liekan 保留 Umami 的无 Cookie 默认、SDK 名称、采集字段和响应形状。读取政策 v5 将浏览 PV、UV、访问、跳出、时长、来源及导出统一限定到有身份依据的浏览事件：来源为公共浏览器，当前分类为 `browser`，事件环境 `scope=browser` 且 `identity_available=true`，并通过网站策略及治理排除。UV 在整个所选窗口按 `session_id` 去重。缺少身份或分类依据的原始事件继续保留在流量质量审计中，覆盖信息仍包含这些事件；部分覆盖时展示已纳入子集的指标并说明范围，全无身份依据时明确显示不可用。默认匿名标识使用可信入口 IP、完整 UA、月度盐和可选用户 ID；同一人换网络、浏览器或身份可能产生多个标识，多人共享网络和 UA 也可能合并。该指标代表可观察的匿名标识，仍可能包含未识别自动化。

## 采集与去重

跟踪器在页面内按网站 UUID 与实际采集地址注册一次。重复插入同一脚本只发一次初始 PV。不同网站和采集地址分别工作。连续 SPA 跳转立即保存各次地址和来源，延迟发送时读取更新后的页面标题。正常刷新、不同路径和手动事件仍分别计数。

新版跟踪器在安全随机数可用时，为每个逻辑发送附带可选 `payload.eventId` UUID。PostgreSQL 网站事件与性能事件按网站和 UUID 原子去重：相同内容和内部来源范围重试返回原事件的会话与访问 ID，确认令牌使用当前时间并保留 Umami 响应形状；同一 UUID 换内容或来源范围返回 409。事件、属性、收入、质量证据和去重凭据在一个事务内提交，写入失败可用原 UUID 重试。没有 UUID 的旧脚本继续采集，相同内容的独立刷新不会被时间窗口猜测合并。`identify` 保持上游语义，此阶段不使用其 UUID 去重。ClickHouse、短链接和像素继续使用上游流程。

## 分类证据

新增的独立质量表保存分类、原因、规则版本、官方范围版本、证据可用状态、规范化主机名和采集来源。该表不保存原始 IP 或完整 UA。去重凭据只保存内容的 HMAC 摘要。

| 分类 | 证据与默认处理 |
| --- | --- |
| `browser` | UA 与普通浏览器相容；保留。此分类无法证明访问者为真人。 |
| `automated` | 已知自动化 UA、明确的浏览器自动控制信号，或可信入口 IP 命中新鲜的官方 CIDR；默认排除。 |
| `suspected` | 公共采集中的旧版生产者覆盖字段；默认保留，可单独审计。 |
| `unknown` | 缺少浏览器分类依据，保留原始审计与覆盖信息。缺少质量行、来源未知及旧版关闭检测的记录同样保留审计。 |

来源分为公共浏览器、经过网站管理授权的服务端采集、兼容旧版覆盖字段。公共 `/api/send` 继续接受 `ip`、`userAgent`、`browser`、`os`、`device` 和主动提供的 `timestamp`；它们归入兼容生产者来源。需要带原时间补报的集成使用鉴权服务器通道。分类器接收原始 payload，服务器补出的默认时间不会触发此兼容分类。

官方范围沿用现有 worker 每小时更新的已审核官方来源。浏览事件入库前完成匹配，并保存当时版本。只有配置了 `CLIENT_IP_HEADER` 的受信任入口，或认证服务端的 IP 声明，能用于官方范围判定；任意转发头的存在无法建立信任。入口必须剥离客户端伪造头，并覆盖该配置头。Cloud 模式沿用受信任的 `x-umami-client-ip` 入口。公开请求按服务器接收时间校验范围有效期，事件时间独立保存。超过七天、缺失或异常时，范围证据降级。读取失败仅复用同目录、用途、来源 ID、URL 与解析器的有效成功快照。当前目录故障回退最多 60 秒；已知撤销立即失效，历史固定目录不授予新请求权限。

短停留、单页、没有点击、数据中心 ASN 和普通 ChatGPT 引荐均不构成此阶段的自动化硬判据。`DISABLE_BOT_CHECK` 只以 `1`、`true` 表示开启兼容开关；网页已取得的强自动化证据始终保留。来源及证据在采集时固化；更新规则作用于后续事件。

采集规则 `traffic-quality-v2` 增加两项证据：跟踪器在 `navigator.webdriver === true` 时发送可选布尔字段 `payload.webdriver: true`，判定原因为 `browser_webdriver`；公开请求自身的 UA 命中机器人时，即使 payload 覆盖为普通浏览器 UA，也保留 `request_ua_bot` 证据。授权服务端采集的 HTTP 客户端 UA 与其声明的访客 UA 分开处理。`webdriver` 缺失或为 false 不证明真人，非法类型返回 400。自动控制信号在 `beforeSend` 回调之后加入，旧跟踪器继续兼容；不新增 Cookie、浏览器持久标识或原始 IP/UA 存储。

采集规则 `traffic-quality-v3` 复用日志识别的已审核 HTTP 蜘蛛注册表，以完整产品 token 补充通用 `isbot` 检测。浏览器 UA 附带 ChatGPT-User、Claude-User、Perplexity-User 等已登记身份时，记录 `crawler_ua_token`；公开传输 UA 的同类证据记录 `request_crawler_ua_token`。多个已登记身份冲突仍能判定自动化，不指定厂商。授权服务端的传输 UA 不用于判断其访客；引荐来源、路径、短停留、缺少请求头及 webdriver 为 false 均不会新增自动化判定。后续 v4 对网页保留不可关闭的强证据排除底线。

v3 仅作用于新采集。历史质量表不保留完整 UA，无法据此重新识别旧记录，也不会把未识别访问追认为真人。总览使用“访客（UV）”“浏览 PV”，并显示当前策略及未识别自动化的限制；“流量质量”可直达质量审计。浏览器特征、已知自动化、待核查、证据未知分别展示 PV、仅有 PV 的匿名访客 UV、纳入 PV。分类 UV 可以重叠；主指标仍由统一有效视图去重。

日志中未登记厂商身份的 UA 若命中通用机器人检测，显示“自动化特征 · 身份未核验”。该提示保留原有未知身份和 AI 统计范围；它不建立官方身份、不追溯修改浏览事件质量，也不能证明该日志请求执行过浏览器采集脚本。

质量审计及策略预览支持可选 `path` 精确路径参数，保留尾部斜线；`/cases` 和 `/cases/` 可分别核对。路径进入绑定参数与游标签名，最多 2,000 字符。路径、分类和来源筛选作用于汇总及明细；采集诊断、请求上下文和行为观察维持各自明确的全站窗口。观察零命中无法排除低频分散的自动化。

v2 使用原有自动化分类及统一有效视图，不改变统计策略或历史分类。可疑访问者隐藏自动控制信号、伪造普通 UA 或更换出口时仍可能进入浏览器相容类别。升级时先更新所有采集服务端，再更新脚本并检查实际加载的 `script.js` 与缓存覆盖；旧服务端会剥离新字段，同一 UUID 跨版本重试可能因内容指纹不同返回 409。旧事件缺少该信号，无法凭新版规则追认其身份。

## 统一策略与审计

网站所有者或管理者通过 `PUT /api/liekan/websites/{websiteId}/traffic-quality` 设置完整策略：

```json
{"mode":"standard","allowedHostnames":[]}
```

读取政策 `traffic-quality-browser-population-v4` 首先核对数据库中的真实资源，网页只接受 `source=browser` 与类型 1、2、5。类型 3、4 只服务真实链接和像素，不能利用网站 UUID 进入网页指标。授权服务器、兼容覆盖来源及来源缺失历史不进入浏览 PV / UV，仍保存在原始审计；短链接与像素保留上游独立语义。浏览器来源内，`standard` 排除自动化，`strict` 额外排除可疑，旧 `raw` 配置保留审计记录，主报表执行标准过滤。全部来源的原始量通过质量审计查看。策略应用于 PostgreSQL 浏览总览、趋势、来源、地域、设备、事件、转化、收入、分享与导出的共同读取层，筛选候选值仅纳入所选窗口内有有效事件的会话，属性和收入跟随其父事件。改变策略同步增加统计版本，跨进程缓存随版本失效。原始事件保持完整，历史缺失证据归为未知。界面布局保持现状。

热图与录制按关联的 `(website_id, session_id, visit_id)` 是否有纳入的访问筛选。没有关联访问的历史记录保留在原表、状态未知，不进入有效录制视图；混合访问包含至少一个纳入事件时保留该访问的录制。安装验证沿用原始采集证据；ClickHouse 使用已有统计及日期范围接口。

`allowedHostnames` 默认为空，采用审计口径。填写列表后按精确主机名筛选，统一大小写、国际化域名、`www` 和端口，不自动扩展子域名。主机名由采集内容提供，这项设置用于统计管理。有效 Origin 与已配置主机冲突时退出主报表；缺失 Origin、`Origin:null` 和跨域 collector 单独出现均不构成自动化证据。原始审计可查看各来源。审计接口返回实际主机名，便于核对多域名接入。

安装验证与数据来源连接状态依据原始采集记录。有效统计为零时，已收到数据的状态仍然保留；安装响应中的 `browser` 元数据与统计结果使用各自明确的口径。

`GET /api/liekan/websites/{websiteId}/traffic-quality` 返回策略、各类事件/PV/匿名标识数、缺失判定数、当前纳入数与最多 100 条质量明细。可用 `startAt`、`endAt` 毫秒时间戳、`classification` 和 `page` 查询，单次时间跨度最多 366 天。各类 UV 可能有相同访客，不应相加作为整体 UV。

服务端生产者使用 `POST /api/liekan/collect`，携带完整登录令牌或具有该网站管理权限的 API Key，正文继续使用 Umami 网站采集格式。公开分享身份、部分二步验证身份和无网站管理权限身份无法写入或修改策略。公共采集中的 Authorization 字段不会自动建立服务端信任。

## 请求日志与浏览指标

“今日总请求”按当前查询时区的今日日志窗口计数，只排除已列明的静态后缀。私有页面默认使用账户保存的时区，新分享使用创建时保存的时区。该值包含机器人、API、探测、失败请求及不同方法。访客 UV 使用界面所选浏览窗口，趋势图可以使用独立窗口。日志请求总量与浏览 PV/UV 的单位、来源和窗口各有定义。

本阶段不会补造历史分类，也不会根据截图反推真实偏高比例。可在真实网站上先查看质量审计，核对重复脚本、主机分布、分类占比和所选窗口；原始日志中未采集的证据需要后续采集后验证。

服务端日志用于请求规模、爬虫识别及覆盖诊断。日志导入写入 `liekan_log`，浏览事件写入 `website_event`；人类 UV 从有效浏览事件按 `session_id` 去重。日志 IP 数、请求数、按日 UV 之和均不能替代整个窗口内的浏览 UV。两路数据缺少共同的可信事件标识时，只能按时间、路径和来源交叉核查，不能据此合并或扣除具体访客。

## 与其他统计系统核验

先固定同一站点、主机集合、时区和完整自然日，例如北京时间某日 00:00 至次日 00:00，记录实际毫秒边界和读取时间。默认今天按账户时区的自然日定义，初始时区为 `Asia/Shanghai`；明确带有 `date=24hour` 的旧链接继续使用按小时取整的滚动窗口。对账宜选择自定义的完整自然日，并在次日等待各系统入库完成后读取。日期定义见 [日期与时区](date-ranges.md)。跨日 UV 在整个窗口去重，不能相加每日 UV。

按以下顺序核验，保存每轮结果和规则版本：

1. 在质量面板记录原始/纳入/排除 PV 与 UV、分类、来源、主机、缺失判定、规则版本及诊断覆盖。同一窗口的身份证据完整时，原始 UV 减去纳入 UV 等于完全排除的 UV；证据不足时相应指标保留为空并显示覆盖情况。各分类可能共享访客，分类 UV 无法相加。
2. 检查网站实际脚本覆盖页面、重复插入、SPA 路由、服务端事件生产者、可信 IP 入口和采集版本。对同一普通浏览器的正常刷新与路由访问，PV 按有效浏览累加、同窗口 UV 保持一个；匿名标识受网络与完整 UA 变化影响。
3. 使用单页正常浏览、普通 UA 的自动化浏览器、已知 bot UA、公开 UA 覆盖、授权服务端采集分别验收。自动化事件保留在原始审计，默认统计和导出统一排除；普通单页短访问保留。
4. 对余量按小时、页面、访客单页占比和查询参数结构查找集中模式，再与网站访问日志核验。重复分页参数和持续分散请求可作为排查线索。行为观察的零命中仅表示没有满足该规则，低频分布式自动化可能完全低于阈值。
5. 与 GA4 优先比较同范围的 Total users，并限定网站浏览事件；默认报表的 Active users 有参与条件，另行记录。百度记录明确的 UV 指标、过滤设置、部署覆盖与统计范围。连续比较至少七个完整自然日，报告每日绝对差和相对差，逐项归因。没有基准数据时不承诺某个误差比例。

参考实现与边界：

- [Umami 采集源码](https://github.com/umami-software/umami/blob/master/src/app/api/send/route.ts)使用 UA 机器人识别和匿名会话标识；本系统保持其兼容标识语义，额外保存可审计分类。
- [Plausible 事件处理源码](https://github.com/plausible/analytics/blob/master/lib/plausible/ingestion/event.ex)包含 HeadlessChrome/UAInspector 过滤；[匿名标识说明](https://plausible.io/data-policy)描述按网站、IP、UA 与每日盐生成标识。每日盐与本系统默认月度盐具有不同的跨日去重边界，不能靠调整盐周期消除机器人。
- [Matomo 日志导入源码](https://github.com/matomo-org/matomo-log-analytics/blob/master/import_logs.py)独立处理机器人、静态资源、错误与重定向；[官方日志口径说明](https://matomo.org/faq/log-analytics-tool/will-there-be-differences-in-the-stats-or-data-between-awstats-and-matomo/)说明日志与 JS 的识别能力差异。日志中未命中机器人规则的请求仍缺少真人证明。
- [GA4 已知机器人排除](https://support.google.com/analytics/answer/9888366?hl=en)与[用户指标定义](https://support.google.com/analytics/answer/12253918?hl=en)分别说明过滤与 Total/Active users 区别。平台识别、部署覆盖、广告拦截和身份算法不同，需实测解释差异。

## 本地验证

`pnpm liekan:verify` 包含源码检查、生产构建、独立 Docker 数据库迁移与恢复、API 和视觉验收，随后运行流量质量的真实数据库测试。后者自动创建并清理带唯一归属标签的网络、卷与容器，默认绑定 `127.0.0.1:3324`，不会连接原有应用或数据库。

已构建且 OCI revision 与当前 HEAD 一致的候选镜像，也可单独运行 `pnpm test:traffic-quality`。`LIEKAN_TRAFFIC_IMAGE` 可指定候选镜像，`LIEKAN_TRAFFIC_PORT` 可指定 3300 至 3399 中空闲的验收端口（排除 3302、3305、3352）。测试覆盖并发重试、事务回滚、分类与范围证据、策略和缓存、统计与关键词导出、原始采集状态、重复迁移、重置及删除。

设置 `LIEKAN_TRAFFIC_UI=1` 会额外打开隔离的无头浏览器，验证中英文桌面和移动页面的质量入口、分类及路径筛选。开发机使用已安装 Chrome，CI 使用 Playwright Chromium；浏览器仅访问测试创建的临时网站。

## 质量面板与策略预览

网站设置的采集设置提供“浏览流量质量”入口。面板使用当前时间范围和时区，分类、来源、主机及路径筛选应用到审计计数和明细。网页统计对照中的 PV 使用 `event_type=1`，UV 对该集合中的 `session_id` 分别去重。分类汇总中的事件计数保留事件级口径；访客 UV 只计算有页面浏览的标识，自定义事件与性能事件不会单独产生该 UV。排除 PV 可相加还原原始 PV；身份证据完整时，排除 UV 表示完全失去纳入页面浏览的匿名标识；证据不足时该指标为空，分类 UV 不能相加。

`POST /api/liekan/websites/{websiteId}/traffic-quality/preview` 接受 `policy` 与 `range`，通过共享网站锁复核管理权限，在同一快照内计算当前和拟议结果。预览不写入策略、历史分类或缓存版本。保存接口允许附带 `expectedRevision`，冲突返回 409；旧客户端省略该字段时保留原有保存行为。每次保存原子写入操作者、前后配置和版本历史。界面恢复历史配置先载入草稿并预览，再生成新版本。

审计新增 `totals`、`diagnostics`、`history` 和 `nextCursor`，保留旧 `page` 查询。游标绑定站点、时间、筛选与策略版本，使用事件时间的微秒精度和事件 UUID 排序。前端只在打开、切换条件和手动刷新时读取。

诊断计数与事件、属性、收入、质量证据和去重凭据在同一事务中提交。成功新增、其中带 UUID 的新增、成功去重分别计数；冲突、参数校验失败、数据库失败和未到达采集接口的请求均不进入分母。计数按服务端接收分钟和 32 个分片存储，响应返回实际分钟桶边界、采集起点和保留起点。零分母比例返回 null，未采集的历史显示缺失。新诊断只覆盖 PostgreSQL 网站事件和性能事件，保留 30 天。

## 浏览行为观察

`GET /api/liekan/websites/{websiteId}/traffic-quality/risk` 提供独立观察结果。规则 `browser-behavior-v1` 使用原有会话与访问标识，对已经去重的浏览 PV 分析接收时间和路径重复特征；新增证据不保存完整 UA、原始 IP 或访问路径。观察结果不参与 `standard` 或 `strict`，也不写回 `suspected`。

窗口为五分钟，每分钟推进，延后两分钟处理，为采集事务提交留出余量。持续高频需要一分钟至少 60 PV 且窗口至少 120 PV；机械节律需要至少 30 PV、至少 60 秒跨度、间隔中位数 0.5 至 10 秒、相对中位绝对偏差不超过 5%，且至少 90% 间隔位于中位数的 ±5%；路径高度重复需要至少 30 PV、至少 60 秒跨度和同一路径占比至少 90%。命中至少两项进入建议核查。网络集中到达、共享标识和正常自动刷新均可能产生线索，数值用于复核。

现有 worker 使用独立 `liekan-browser-risk` 队列，每十秒唤醒，每批最多处理十个网站。每个窗口先按接收时间和事件 ID 读取至多 10,001 条质量证据，再按主键关联事件；取样预算包含自定义事件和性能事件，行为分析使用其中的 PV。超过 10,000 条输入的窗口记录部分覆盖，并停止生成该窗口的行为结论。单站异常记录失败状态、退避一分钟并继续处理其他站点。每次写入检查网站状态、epoch 和规则版本；重置删除清理进度和派生结果。历史缺失、队列延迟、未观察窗口及超出 30 天保留期的范围均无法证明无风险。

风险明细按接收时间窗口展示。质量面板读取当前时间范围内的全站观察结果；风险 API 仍支持可选分类、来源与主机筛选，忽略审计专用的路径参数。特征值来自完整观察窗口。影响预览对选定事件时间范围内的当前有效事件去重，重叠窗口不会重复计数。诊断、观察覆盖和业务事件时间分别标明。

可在应用容器内执行 `node dist/liekan-worker.mjs --observe-browser-risk-once` 处理一个有界批次，用于维护与隔离验收。它使用现有数据库配置，不修改统计策略。ClickHouse 返回显式不支持状态，原生 ClickHouse、链接和像素采集继续沿用原流程。

当前升级追加 037 迁移，保留原事件和原分类。回退候选必须包含本轮来源、类型和已知自动化硬边界；治理与历史分类覆盖分别撤销，保留新增结构。至少七天真实样本的误报校准独立记录，观察期结束不自动启用行为排除。

诊断计数随范围返回 `complete`、`partial` 或 `missing` 覆盖状态，以及实际观测边界。启用前、过期和未来范围的缺失计数返回 `null`；跨越边界时仅汇总保留范围内已观测的部分。当前分钟按分钟桶显示，失败请求不进入分母。

统计证据、采集对账、观察保留期与风险工作流详见 [流量证据与统计口径](traffic-evidence.md)。

## 浏览器总体 v3 与持续治理

采集先核对真实网站、链接或像素资源，再确定来源、自动化和身份资格。网页、兼容生产者、鉴权服务端、已知自动化与身份不足的存储关联使用独立命名空间。会话、属性、身份关联、事件、质量、环境快照和可选收据一起提交；任何失败均回滚。属性更新和身份关联同时失效历史统计缓存。

自有会话、属性和身份关联旁表记录来源。设备维度采用事件环境快照；历史缺失快照、属性来源或身份依据保持未知，不能通过新一次浏览为整个旧会话补信任。环境旁表不保存原始 IP 或完整 UA。公开接口可以被程序模拟，已过滤已知自动化的浏览器指标仍存在未识别自动化。

读取政策 v5 将环境分组、筛选候选、导出与录制关联信息绑定到各自范围内的有效事件快照。后续访问改变屏幕、设备或语言时，旧时间窗口仍使用原事件的环境；旧事件缺少快照时保留未知。响应中的 `metricScope=qualified-browser` 表明所有浏览指标均使用同一已纳入子集，部分覆盖不再清空该子集的身份指标。没有此范围声明的旧响应继续保留原来的缺失保护。读取版本进入跨进程缓存键、持久汇总与新 AI 事实的统计版本，升级后重新计算，历史保存的 AI 回答继续保留其原版本。链接、像素与 ClickHouse 保持原口径。

规则 `traffic-quality-v4` 使用当前发布注册库的审核 HTTP token；专用 CIDR 需要独立的 `browserExclusion=dedicated_crawler` 用途授权。旧目录通过已有升级草稿审核发布，缺失该标记的范围不自动获权。Kimi 三类、HySpider 等专用 feed 使用统一路径；共享云地址、robots-only token、产品品牌和 AI 引荐域名不会据此成为爬虫身份。范围只证明自动化，官方厂商认证继续使用日志证据规则。

治理入口 `POST /api/liekan/websites/{websiteId}/traffic-quality/exclusions` 只允许完整网站管理身份。`preview` 接收单个已处理完整五分钟窗口及候选访问，最多 10,000 个事件；`confirm` 校验摘要、权限、网站 epoch、政策、分类规则、目录、历史代际与治理 revision，预览 15 分钟失效。候选集合的每条事件都需具备可靠身份依据；缺失输入形成的内部关联仅保留行为观察，不能作为访问级排除依据。确认冻结具体事件集合，晚到事件需要新的预览。`revoke` 撤销单个集合；重叠集合独立生效，使用 EXISTS 避免行倍增。

已确认集合使用同一治理版本下的游标分页，可继续加载并撤销较早记录。候选访问分别预览，同一窗口中证据不足的候选不会阻挡其它候选。

治理成员与行为观察表独立。清理超过 30 天的观察不会撤销已确认排除。网站重置推进 epoch，旧预览不能确认，旧集合停止作用于新周期。所有治理变更与统计版本同事务提交。一次性历史修复继续只读取既有 campaign 的已确认代际，持续治理不创建第二个历史修复 campaign。

预渲染只在激活后发送自动首个 PV，纯预取不计。短停留、后台标签、无点击、WebView、企业网络、AI 引荐与可选请求头缺失不会单独触发自动排除。BFCache、SPA/query/hash 保持已有语义；自动首个 PV 与手动首个 PV 同开需要部署者明确选择。

新增隔离验证：`LIEKAN_HUMAN_TEST_DATABASE_URL=... pnpm exec tsx tests/liekan/browser-population.integration.ts`。脚本仅接受本地测试数据库，为每次运行创建唯一自有 schema，执行后仅清理该 schema。

v5 指标回归：`LIEKAN_HUMAN_TEST_DATABASE_URL=... pnpm exec vitest run src/lib/liekan/upstream/human-metrics.integration.test.ts`。覆盖原始/合格事件对账、Umami 计算公式、部分与全无身份、链接/像素、持久汇总与原始缺口合并，以及旧版本清单失效。测试创建并清理自有 schema。

接收观察诊断的 `received-browser-identity-v1` 单独衡量原始接收事件的身份输入覆盖；它保留接收时间和原始分类，计数可与当前策略下的正式浏览总体不同。跨源日志对账与请求/引荐比值继续要求完整浏览身份覆盖。


匿名身份编码 v4 使用带字段边界和来源命名空间的元组，避免 IP 与 UA 直接拼接产生同一标识。网站新事件切换到新标识；旧事件、旧 session ID 和签名追踪令牌继续保留，新请求重新计算身份与访问标识。全局 crypto.hash、链接、像素和 ClickHouse 的原生标识保持兼容。跨升级窗口无法证明新旧标识属于同一真实访客，响应单独提供 qualifiedVersions，界面将相关身份指标标为估算并提示可能重复；只有未纳入旧事件时不触发此提示。历史数据不按猜测合并或重写。

趋势图的 trendPopulation 独立记录图表日期范围的身份覆盖；卡片范围和趋势范围分别处理可用性。对照期缺少身份时保留空缺，来源变化与相对日期序列不将其补成零；真实空窗口继续返回零。

正式浏览指标要求事件关联的会话属于同一网站；缺失或指向其他网站的会话留在观察覆盖中。此项报告资格校验保留原始接收身份判定，身份与会话修复后通过统计版本和缺口重新计算。
