# 自动日志接入

网站设置的“数据接入”提供 JS 安装、Cloudflare 授权、服务器一次安装和接入检查。每一步都可以跳过检查并完成设置；保存进度、连接配置、真实日志接收、后台处理分别显示。网站 JS 采集执行脚本的浏览访问，服务器与 CDN 日志补充蜘蛛请求。

## 平台运行配置

运行环境使用 Node 22，生产镜像固定 22.23.4，支持 PostgreSQL 15 / 16；标准 Compose 首次安装默认 16，既有 15 实例保留原大版本。应用和独立日志处理进程共用主库。启动顺序为上游迁移、Liekan 增量迁移、固定队列初始化、应用、处理进程。队列使用 pg-boss 12.36.0，固定在 `liekan_jobs` schema；供应商 DDL 由独立初始化器执行并记录版本及校验值。应用及 worker 禁用运行时自动迁移，升级队列版本需要单独审核迁移。

- `LIEKAN_PUBLIC_URL`：对用户开放的 HTTPS 网站根地址，也是日志接收与 OAuth 回调地址。网站设置页面应通过同一域名访问。
- `LIEKAN_LOG_CREDENTIALS_KEY`：32 字节随机密钥的 Base64，用于加密供应商凭据。
- `CLOUDFLARE_OAUTH_CLIENT_ID`、`CLOUDFLARE_OAUTH_CLIENT_SECRET`：平台的服务器端 OAuth 应用配置。回调地址为 `/api/liekan/oauth/cloudflare/callback`。
- `LIEKAN_AGENT_SIGNING_KEY_FILE`：构建机上的 Ed25519 私钥文件路径，供 `pnpm liekan:build-agent` 签名。私钥保留在受控构建环境；安装资产位于生成目录 `public/liekan-agent`。本地验收可加 `--development-key` 使用 `.local` 中的专用测试密钥；正式环境使用平台维护的签名密钥。

Cloudflare 应用应按[官方 OAuth 指南](https://developers.cloudflare.com/fundamentals/oauth/create-an-oauth-client/)中的可选权限配置读取匹配 Zone 与管理 Logpush 所需的最小权限，并完成供应商的应用登记、域名验证及可见性要求。Zone 与 Logpush 的实际可用性在授权和任务创建时核对。账户套餐、日志字段和费用由 Cloudflare 决定，连接前需要用户确认。官方权限标识通过授权账户的 scopes API 获取，避免猜测权限 ID。

授权请求默认显式携带 `zone.read logs.read logs.write`。在 OAuth 客户端中登记相应的 Zone 读取及 Zone Logs 读写权限；账户级 Logs 权限与 Zone Logs 权限的作用范围不同。以官方 scopes 目录和当前账户允许配置的权限为准。需要调整时，在私有 `.env` 设置 `CLOUDFLARE_OAUTH_SCOPES`，使用空格分隔；标准 Compose 会将它传入应用。修改后重建应用容器以加载配置，并重新发起授权。该变量不会为客户端或账户自动添加权限。

Logpush 返回“当前账户未启用”时，连接显示独立的能力提示；缺少 Zone 日志权限时显示权限提示。两者暂停该来源并保留已有接收凭据，不再统一要求按“授权失效”重新连接。真实认证失败仍会撤销接收授权。Cloudflare 已提供[各套餐自助启用及按用量计费](https://developers.cloudflare.com/changelog/post/2026-09-30-logpush-usage-based-pricing/)，具体数据集、账户启用状态和费用需在供应商处确认，也可改用服务器采集。应用不会自动启用计费服务。

应用与日志 worker 的 Cloudflare 请求失败会输出 `[liekan-cloudflare]` 结构化诊断。`operation` 区分 `token`、`api`、`revoke`；HTTP 失败记录状态和受限的数字供应商错误码，网络失败记录允许列表中的异常名称与原因码，例如 `ENOTFOUND`、`ETIMEDOUT`、TLS 证书错误或 `redirect-not-allowed`。不记录请求头、请求体、完整 URL、供应商响应正文、OAuth 授权码或令牌。用户界面继续使用经过控制的错误提示；排查时按失败阶段核对 DNS、连接、TLS 或供应商能力。

能力入口根据公网地址、队列登记、近期 worker 心跳、签名安装资产和 OAuth 配置显示“可用”或具体待配置原因。待配置时，主操作为“开始配置”；普通网站用户可“查看配置说明”，复制要求交给部署管理员。引导在原页面提供公网地址填写、环境配置与回调地址复制、部署步骤和重新检查，按接入方式展示全部相关检查项。配置仍由部署环境管理，页面填写仅生成说明；密钥不会返回浏览器。重新检查核对运行配置与心跳，外部 HTTPS 连通性和真实日志到达在连接后验证。检查通过后恢复授权链接或安装命令生成，用户也可延后配置完成网站设置。连接探测仅记录测试到达，真实数据与处理状态由实际日志更新。部署代理应过滤 OAuth 回调查询参数及 Authorization 请求头，避免将临时授权码和接收凭据写入访问日志。

## 服务器安装

### Docker / 宝塔（推荐）

在网站的数据接入页面选择“服务器一次安装”，默认使用 Docker。可以生成一次安装命令，在宝塔终端执行；也可以先下载本站专属部署包，上传并解压到公开访问目录之外，在宝塔管理员终端执行 `sh start.sh`，普通账户使用 `sudo sh start.sh`。部署包含采集器、固定运行环境的 Dockerfile、编排模板和安装说明；包含的接收地址和网站标识供安装使用，配对码与长期凭据不进入下载包。

目标服务器需要 Linux x64/arm64、可运行的 Docker Engine 和 Docker Compose V2，以及 Linux util-linux 提供的 `flock` 锁工具。容器运行环境固定 Node 22.23.4 Alpine 及镜像摘要，宿主机无需安装 Node 或 systemd。Docker 仍依赖宿主机内核、镜像下载网络和容器权限；安装器通过真实构建及容器检查验证可用性。首次安装在目标服务器构建小型采集镜像，后续升级按已校验部署包构建版本镜像。

在宝塔当前网站的日志设置中确认访问日志路径，通常位于 `/www/wwwlogs/`。每个网站独立部署，填写该网站 Nginx / Apache Combined 访问日志。路径支持字母、数字、点、下划线、短横线和斜线。只读挂载包含当前日志及其轮转文件的目录，避免仅挂载单个文件导致轮转后无法读取。容器使用非 root 用户及日志文件的用户组，日志必须具有相应读取权限，轮转目录必须可读取和遍历。请优先使用网站专用日志目录；共享目录中其他日志不会被采集。安装器不会更改日志权限、SELinux 标签或网站服务。

安装顺序为 Docker 检查、部署包 SHA-256 校验、镜像构建、日志路径/权限/格式检查、缓存写入检查、公网 HTTPS 健康检查、一次性配对、容器就绪检查。完整日志样本格式不符时停止；空文件允许启动并明确等待新增日志。配对码有效期十分钟且仅使用一次，建议先准备环境再生成；过期后在后台重新生成，同一部署继续安装。

安装、升级和停止使用同一把系统文件锁；进程退出或服务器重启后由内核释放，锁文件继续保留。取消安装会立即结束脚本，保留现有配置和持久卷。日志路径在解析父目录符号链接后再次校验，拒绝换行及不支持的字符，避免路径内容进入编排配置。

配置及编排保存在 `/opt/liekan-agent-docker/<网站ID>`，长期接收凭据、加密缓冲和采集位点保存在独立 Docker 持久卷。配对码通过标准输入交给容器，容器环境变量、编排文件和镜像均不含长期接收凭据。容器根文件系统只读，关闭 Linux capabilities，不挂载 Docker socket，不监听公网端口，仅向统计服务发送 HTTPS 请求。

重复安装先只读核对已有来源的接收授权，授权有效时复用配对及进度；网络异常保留原配置并停止安装。凭据已撤销时可使用新配对码重连，旧来源配置和缓存继续保留。Docker 配对同时核对网站标识，错误网站的配对码会在消耗前被拒绝。配置绑定规范化后的宿主机日志目录及文件名，目录改变或接收地址冲突时停止。候选编排在环境检查完成后切换并重新创建容器，升级启动失败恢复旧镜像。停止采集时，管理员终端运行 `sh start.sh --stop`，普通账户使用 `sudo sh start.sh --stop`，配置、持久卷和历史数据保留；网站后台的“断开连接”用于撤销接收权限。首次自动采集从文件末尾开始，历史日志继续通过手动导入补充。

Docker 部署包与直接安装包独立检查可用性。部署管理员执行 `pnpm liekan:build-agent`，使用受控签名密钥生成带 Docker 资产的签名清单并重新构建应用镜像。部署包下载需要完整登录和网站管理权限，下载不会创建或消耗配对码。安装检查分别展示采集服务连接、真实日志接收、后台处理、积压及本站 AI 蜘蛛匹配；已收到日志且 AI 匹配为零时明确显示暂未匹配。

### 直接安装到系统

支持 Ubuntu 22.04/24.04、Debian 12，Linux x64/arm64，systemd，以及 Nginx / Apache Combined 访问日志。每个来源读取用户指定的当前网站日志文件。安装器核对文件、日志用户组及目录权限，创建专用服务账户，授予现有日志组只读访问，并通过 systemd 限制写入到该来源的缓冲目录。请使用网站专用日志及只读用户组，保持日志轮转后的组和读取权限一致；root 组日志需要先配置只读日志组。

服务隔离保护 `/home`、`/root`、`/run/user` 和临时目录；这些目录中的日志会在消耗配对码前被拒绝。建议使用网站专用的 `/var/log` 目录。服务启动须通过绑定当前进程的就绪检查；升级失败会恢复此前运行包和服务配置。

安装页面生成十分钟有效、仅能配对一次的命令。命令先核对安装引导 SHA-256；引导使用内置公钥验证签名清单，再验证对应架构安装包。运行时采用官方 Node 22.23.4，构建时核对官方发布校验值。长期接收凭据写入本机受保护配置，不出现在安装页面。

服务配置位于 `/etc/liekan-agent/<来源ID>.json`，缓冲位于 `/var/lib/liekan-agent/<来源ID>`，服务名为 `liekan-log-<来源ID>.service`。首次启动从文件末尾开始；健康状态到达后切换为主要来源。已有日志可通过手动导入补充未被自动来源覆盖的时段。

采集器使用加密缓冲、持久读取位点和确认位点。断网后保留批次并按原标识重传；收到与请求绑定的持久确认后删除缓冲。缓冲上限为 256 MiB，最早批次超过 24 小时后暂停读取并显示提示，保留现有缓冲。完整行才进入批次，超长行明确计入格式错误。支持 rename/create 轮转；copytruncate 和 inode 复用会创建新文件代次并报告可能缺口。

临时网络异常保留最后确认的采集授权，继续本机缓冲；明确暂停或撤权后停止读取。读取和传输重试分别安排，已保留的数字、日期后缀轮转文件可以恢复。目录扫描最多 256 个候选，最多同时保留 32 个文件句柄；超过范围或文件已删除时会报告缺口。首次文件位点在激活来源前持久保存。重置同步保留位点，并将未确认缓冲按新代次重新提交，由服务器过滤重置前的日志。

升级与卸载由已验证的安装引导执行：升级参数 `--url <公网根地址> --upgrade <来源ID>`，保留配置和缓冲并切换运行包；启动失败时恢复原包。卸载参数 `--uninstall <来源ID>`，停止服务并保留配置及缓冲。后台“断开连接”撤销接收权限并保留历史统计；本机卸载需在服务器执行。

## Cloudflare 授权

授权流程绑定网站、创建者、网站管理权限、域名、重置代次、短期 state、PKCE 和 HttpOnly 浏览器 Cookie。回调仅暂存加密授权结果；用户返回网站设置后，使用完整登录确认匹配 Zone 和费用，再由后台创建或复用本平台拥有的 Logpush 任务。

授权凭据在查询 Zone 前进入独立的加密清理台账。授权失败、浏览器流程过期、网站重置或变更后，处理进程保留凭据并重试撤销；确认连接时，凭据和清理责任在同一事务转移到日志来源。清理台账随平台密钥轮换一起重新加密。

Logpush 只接收当前网站域名的 `eyeball` 请求，采样率为 1，包括静态资源、缓存命中及有效拦截请求。所需字段缺失、域名不匹配或无效日志会返回拒绝计数。Ray ID 配合高精度事件时间与请求特征生成事件标识，保持重新分批后的去重能力。

日志输出固定使用 `rfc3339ns`，保留纳秒时间供事件识别，遵循[官方输出选项](https://developers.cloudflare.com/logs/logpush/logpush-job/log-output-options/)。

接入使用[Cloudflare 官方 OAuth 端点](https://developers.cloudflare.com/fundamentals/oauth/integrate-with-cloudflare/)，凭据撤销遵循 [RFC 7009](https://www.rfc-editor.org/rfc/rfc7009)。后台维护检查任务归属、启停状态和重置代次。只有供应商返回 refresh token 时才使用刷新流程；其他过期授权显示重新授权。断开连接、网站变更或权限撤销后，后台禁用属于该来源的远端任务并撤销该授权凭据，记录停用阶段以支持撤销请求重试。供应商授权已经失效时，清理会持续显示待处理，需要账户所有者在 Cloudflare 核对停用结果。

来源切换与重置导致的配置冲突保留授权，允许在网站设置重新确认。恢复暂停任务时先更新完整配置和当前采集代次，再启用任务。平台记录已配置的接收域名，迁移公网域名后仍可核对并停用原有任务；重复清理失败保留重试状态。

HTTP 目标校验兼容 gzip 压缩的 `{"content":"test"}` 和 `{"content":"tests"}`。校验包须为单条 JSON 对象，且仅含上述 `content` 字段；带额外字段或混入其他日志的批次会被拒绝。接收端先核对来源凭据，再记录连接测试时间。校验包不产生访问日志、导入记录或待处理批次。

### 目标校验失败后的恢复

Cloudflare 返回错误码 `1002`、提示 `error validating destination`，且接收端拒绝 `{"content":"test"}` 并返回 `400` 时，先确认运行版本包含两种校验包的兼容修复。其他目标验证失败还需核对公网 HTTPS、来源凭据和接收服务状态。

升级前按[部署指南](deployment.md#备份与升级)保存数据库备份、原 `.env`、定制编排和当前镜像标识，保留原加密密钥。取得已验证的修复源码后，使用现有部署脚本更新应用和后台。本修复无需新增数据库迁移。直接修改容器内 `.next` 文件的应急改动会在重建或升级时被覆盖，应通过包含源码修复的镜像接续运行。

| 当前状态 | 恢复操作 |
| --- | --- |
| 配置中，日志推送暂时异常 | 确认 `log-worker` 健康并保留现有连接，等待后台重新验证目标及创建任务。重试依赖授权仍然有效。 |
| 已暂停，或提示主要来源已变更 | 在网站设置核对来源，确认“设为主要来源”。该操作会切换当前网站的主要自动来源。 |
| 提示授权失效或网站配置已变更 | 按页面提示重新连接，核对网站域名、归属和供应商授权。 |
| 应急修改后已经正常接收 | 保留连接和已有任务，按正常升级流程切换到修复镜像，再核对真实日志接收与处理。 |

连接测试成功后，继续在网站产生真实访问，核对来源启用状态、最近接收时间、最近处理时间和积压。连接测试时间只证明校验包到达。已持久接收的待处理批次由后台恢复；[Cloudflare Logpush 不支持历史回补](https://developers.cloudflare.com/logs/logpush/)，未收到的历史日志需从独立存档按支持格式补录，并遵守自动来源生效区间的重叠检查。缺少副本的时段保留为缺失。应用回退使用兼容当前数据库和授权协议的已验证镜像，恢复细节见[恢复与回退](deployment.md#恢复与回退)。

## 统计与数据保护

每个网站只有一个主要自动来源，按 UTC 生效区间统计；切换来源会结束原区间并暂停原来源。手动导入拒绝与自动来源重叠的日志行，历史已导入数据按生效区间进入有效统计。所有自动批次继续通过导入台账关联日志，保留既有字段和导出契约。

接收入口验证来源凭据、网站归属及创建者当前权限，限制压缩体 5 MiB、解压体 10 MiB、单行 64 KiB、每批 1000 条。原始访客 IP 仅在接收解析过程中使用，脱敏后进入持久批次与队列；查询参数从请求路径移除。持久批次和队列任务在同一事务提交后才返回确认。确认表示批次已持久保存，处理失败和积压在来源状态中单独显示。

后台每 30 秒检查到期的未处理批次，恢复重试耗尽或已过期的队列任务。每轮最多核对 100 批，按上次核对时间轮询，未处理载荷持续保留以支持恢复；网站重置、撤权或断开来源会取消相应批次。完成或明确失败的批次元数据保留 30 天，历史统计通过导入台账继续去重。每网站最多积压 10000 批，每分钟最多接收 1200 批，为每秒 10 批的突发及前一时段流量保留余量；达到限额时返回稍后重试。

事件标识保持跨重试及分批稳定，同标识不同内容会被拒绝。官方 IP 段仅从已审核固定来源刷新，失败保留上次快照，证据过期显示未验证。自动和手动导入共用识别规则。

网站重置递增采集代次，撤销临时配对与授权流程，取消旧批次并更新来源口径；转移、域名变更和删除立即撤销来源接收凭据。处理进程另外独立检查全部来源的创建者权限，供应商维护失败不会延后此检查。跨进程缓存通过数据版本及口径版本更新。

凭据密钥轮换时，先让应用与 worker 使用新 `LIEKAN_LOG_CREDENTIALS_KEY`，将旧密钥暂放 `LIEKAN_LOG_PREVIOUS_KEYS`（逗号分隔，最多三个）。运行 `node dist/liekan-worker.mjs --rekey` 重新加密现有供应商凭据、授权流程及待清理凭据；确认完成后移除旧密钥并重启。APP_SECRET 保持既有统计标识兼容，变更前需单独评估事件去重与来源标识影响。

## 验证

先构建签名采集器资产，再执行 `pnpm test:agent-docker`，在独立 Docker 网络和持久卷上验证部署包编排、日志权限与格式检查、配对、重启续传、日志轮转、断网缓存及凭据撤销后的重连。测试只清理自身创建的资源；本地构建可使用 `pnpm liekan:build-agent --development-key`，生产构建使用受控签名密钥。

`pnpm test:log-ingestion` 验证协议、凭据隔离、压缩限制及采集器恢复。`node scripts/liekan-log-integration.mjs` 在 127.0.0.1:15435 的 Liekan 服务中新建一次性数据库，验证上游和增量迁移、队列初始化、持久确认、来源口径、重置代次及模拟供应商授权，然后只删除该测试库。真实 OAuth 与 Linux 安装验收还需要公网 HTTPS、供应商应用及对应服务器。

加 `--load` 执行隔离容量测试：默认持续 1000 条/秒 15 分钟，再执行 10000 条/秒 60 秒突发，并测量接收、积压消化、查询和连接使用。脚本在同一进程运行接收、PgBoss 处理和报告核心链路；生产 HTTP 接口、独立处理进程及安装服务另外验证。测试检查实际发送窗口、每批接收计数与拒绝情况，积压消化从突发发送结束时计时；资源数值为报告探针采样的观测最大值。结果只适用于测试时的资源与负载，正式部署需按实际配置重新验收。

## 蜘蛛分析扩展

新版采集器通过兼容的 heartbeat 扩展提交已确认游标和批次范围；只有服务端明确协商覆盖能力后才发送声明。服务端检查来源生效区间、处理状态和识别口径，详情见 [AI 蜘蛛归因、风险与访问控制](crawler-control.md)。缺口确认后重新开始覆盖段，已记录缺口保留。

Cloudflare Logpush 在用户明确配置任务时查询数据集可用字段，按可用性追加 `SecurityAction`、`SecurityRuleID`、`SecurityRuleIDs` 和 `CacheCacheStatus`。已有正常任务保持当前字段配置，升级后需要在来源配置流程中重新确认才能启用这些扩展。历史日志不会回填不存在的规则证据。访问控制使用独立 Zone Token，日志授权与规则管理分别维护。

统计证据、采集对账、观察保留期与风险工作流详见 [流量证据与统计口径](traffic-evidence.md)。
