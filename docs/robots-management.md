# robots.txt 管理

网站数据页右上角统一提供「robots 管理」。点击后先展示当前网站的文件概览、可打开的公开地址、最近成功检查时间和规则摘要；服务器授权后显示本机实际文件路径。「概览与建议」按当前页面的统计范围读取爬虫日志，最长取所选范围末 90 天。建议区明确呈现缺少输入、连续性未知、当前允许路径的 403/429，以及当前禁止规则与历史成功请求之间的核对线索。历史日志与当前规则的时间差单独说明。

点击「管理当前 robots.txt」或「编辑与发布」可使用编辑、监控、授权发布和回滚。原「网站设置 → 采集设置 → 编辑 robots.txt」及「AI 蜘蛛归因与控制 → robots.txt 管理」入口继续可用。页面沿用当前网站上下文，支持简体中文和英文。

## 读取、编辑与监控

首次读取前，在「域名验证与线上文件」创建 TXT 挑战，将记录加入网站 DNS，再点击验证。执行公开检查时会重新核验 TXT，请保留记录。手动读取每个网站每分钟最多一次，公开检查共享全局并发额度。公开读取仅访问已验证域名的 HTTPS 443，沿用现有检查器的公共地址、跳转、超时和 256 KiB 限制，自检流量从蜘蛛统计中排除。

「读取线上 robots.txt」更新公开文件快照，保留当前草稿。「将线上文件载入草稿」会明确替换编辑器中的内容。保存草稿有版本检查，多人同时修改时会提示重新读取后合并。

选择蜘蛛和目录路径后，点击允许或屏蔽，将规则写入草稿。`/` 表示全站。目录操作保留其他蜘蛛和范围外的规则；含语法问题、扩展指令或无法确定范围的通配规则时，需要在编辑器中核对。规则先保存，再预览发布。蜘蛛是否遵守 robots 取决于访问方；需要强制拦截时使用现有 Cloudflare 访问策略。

监控间隔可选 15 分钟、1 小时、6 小时，由现有 worker 执行。内容、文件存在状态或域名变化会生成快照，在面板显示未读变更提示。每张快照保留检查域名。404 表示文件不存在，网络错误和异常响应保留上次成功内容并单独显示检查失败。监控不自动修改草稿或服务器文件。

## 授权服务器

服务器助手使用独立凭据，通过出站 HTTPS 连接后台。配对时需使用服务器可访问的后台 HTTPS 地址。运行账户需能读取 robots.txt，并在其父目录创建临时文件、重命名和删除文件。网站所有者、团队负责人和平台管理员可授权与发布；有编辑权限的成员可保存草稿。

`--url` 可填写后台 HTTPS 根地址、带部署子路径的后台地址，或面板提供的完整助手接口地址。根地址 `https://analytics.example.com` 对应 `/api/liekan/robots-agent`，部署地址 `https://analytics.example.com/analytics` 对应 `/analytics/api/liekan/robots-agent`；以 `/liekan/robots-agent` 结尾的完整接口地址会按原接口路径连接，适用于自定义 API 前缀。尾部斜线会规范化。地址须使用 HTTPS，并保持无用户名、密码、查询参数和片段；包含目录跳转、编码斜线或反斜线等歧义路径的地址会被拒绝。

助手支持 Linux 和 macOS 上的受信本地 POSIX 文件系统。使用网站文件所有者或独立服务账户运行；目标父目录及其每一级祖先目录必须属于 root 或运行账户，组及其他用户须无写权限。具有 sticky 位的可信祖先目录可保留，其下一级目录也须属于 root 或运行账户；目标父目录自身须禁止组及其他用户写入。共享写入目录、其他账户拥有的祖先目录和可替换的路径会暂停操作。网络卷及独立权限映射不在此支持范围内。

私有状态目录及其祖先目录适用相同的信任检查，状态目录权限必须为 `0700`。助手会安全创建新的私有目录；已有目录不符合要求时，维护者需先核对归属和权限。macOS 还会检查目录 ACL，拒绝允许权限的条目和无法明确解析的输出；可明确解析的 deny-only 条目可保留。Linux 的 POSIX ACL 写入掩码按目录权限位检查。安全检查错误会显示 `untrusted-directory-owner`、`untrusted-directory-permissions`、`untrusted-directory-acl` 或 `untrusted-state-directory`，核对对应的路径、运行账户和权限后再启动。

1. 从后台下载 `liekan-robots-agent.mjs`，在服务器安装 Node.js 22。
2. 生成十分钟授权码。按后台显示的命令配对，将 `--file` 改为当前网站实际提供的 robots.txt 绝对路径，将 `--state` 改为该账户的私有持久目录。
3. 运行助手。确认后台显示的授权文件与最近同步时间。

配对命令示例：

```sh
node liekan-robots-agent.mjs pair --url https://analytics.example.com --code YOUR_PAIRING_CODE --hostname www.example.com --file /var/www/example/robots.txt --state /var/lib/geoinflow-robots/example
node liekan-robots-agent.mjs run --state /var/lib/geoinflow-robots/example
```

用进程管理器保持助手运行。配对码仅显示一次，十分钟后失效且只能使用一次。私有状态目录保存来源凭据、未确认回执和原文件备份，应纳入受控备份。后台只保存凭据哈希。日志采集凭据与此授权独立。重新配对时使用新的私有状态目录，保留原目录中的备份和回执。

助手固定访问本机授权的 `robots.txt`，远端任务只携带内容和校验值。路径包含软链接、文件存在硬链接、父目录被替换、编码无效或文件过大时，助手暂停该次操作。每个目标目录只允许一个助手运行。

已有文件通过同目录临时文件、同步和重命名替换，保留原权限及属主。SELinux 标签、ACL 和 Web 服务的动态 robots 路由需由维护者核对。助手适用于由指定文件直接提供 robots.txt 的网站；多源站、容器卷或由应用生成的 robots 需先将该路径接入实际服务链路。

## 发布、验证与回滚

发布前，服务器助手须在最近 90 秒内同步过文件。预览保存目标网站、归属、授权助手、草稿版本、原内容和目标内容，十分钟有效。核对完整前后内容并勾选确认后，任务才会交给助手。

助手写入前再次比对原文件校验值，在私有状态目录保存备份及操作日志，再执行替换。文件被人工更新、预览过期或网站归属变化时停止发布。后台收到写入回执后，读取公开地址校验内容；缓存不一致时每 30 秒重查，最长十分钟。界面分别显示服务器写入和公开验证状态。公开验证证明该次读取的响应内容；各蜘蛛刷新缓存的时间由其自身决定。

在发布记录中选择「预览回滚此发布」，核对后确认执行。回滚恢复该次发布前的内容。原文件不存在时，回滚会明确提示删除新建文件。回滚具有独立预览、原文件冲突检查和公开验证。

断线后，助手保留回执并在恢复连接时补交。后台不会自动重复派发已领取的写任务。回执超时会暂停该网站后续发布；助手同步后，管理员可点击「核对未知发布结果」，按原版本或目标版本确认结果。两者均不匹配时，需要先人工核对文件。

撤销授权会取消排队中的任务，并停止新任务领取。已发出的任务保留回执核对能力。网站转移、域名变化或删除会持久暂停助手绑定、配对码和监控，取消预览及排队任务，将已领取任务标为待核对，并中止正在进行的发布公开验证。原凭据仅保留回执和只读文件证据的核对能力；恢复网站原域名或原归属后，发布仍需重新授权。

助手异常退出可能保留目标目录的 `.geoinflow-robots.lock`。维护者须先确认该目录内 `owner.json` 对应的进程已停止，再移除这一个锁目录并重启助手。保留私有状态目录及 `pending.json`，以便恢复回执。

## 部署与验证

升级应用与 worker 前执行 `pnpm liekan:migrate`。数据库恢复时，先停止应用和 worker，再运行既有 `node dist/liekan-worker.mjs --pause-crawler-control`；该命令同时暂停 robots 发布授权和监控，取消预览，并将备份中的排队及已领取任务标为待核对，保留执行记录。恢复后重新核对服务器并授权。增量迁移 067 创建独立的状态、快照和发布记录表，既有 tracker 与日志表保持兼容。助手脚本位于 `public/`，随常规源码和 Docker 构建一起分发。

`pnpm test:robots` 创建独立 PostgreSQL 容器，在 `127.0.0.1:15441` 验证迁移重入、权限、监控、发布、回滚、冲突与未知结果恢复，结束后只删除该测试容器。文件操作和界面回归分别位于 `src/liekan-agent/robots-agent.test.ts` 与 `src/components/liekan/features/robots-management.test.tsx`。
